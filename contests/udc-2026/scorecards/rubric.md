# UDC2026 採点表（rubric）

- 出典: contests/registry.json の criteria（実用度・完成度・挑戦度）と、reports/intel/udc-2026-20261109.md §6 の基準定義。
- 採点対象: 概要登録の下書き（作品①・②）。概要登録は選考ではないため、「この概要の約束で 12/27 本応募の一次審査に臨んだらどう評価されるか」で採点する。
- 手順: 基準ごとに「審査員ならどこで減点するか」を先に書き、その後で点を付ける。改善者の意図ではなく、審査員・自治体職員・技術者の読み方で判定する。
- 字数（作品名20/40字、概要100/200/400字。改行を除く全文字）は採点の前提条件。1つでも超過したらその版は不合格として扱い、点を付けない。

## 実用度（課題と手法・価値の適合）
| 点 | 観点 |
|---|---|
| 1 | 課題と手法が噛み合わない。誰の何の役に立つか読めない |
| 2 | 課題はあるが、手法の結果が誤解を生む（データの欠けを「ない」と示す等）、または既存の公的サービスで足りる |
| 3 | 課題と手法は合う。受け手が広すぎる、または既存サービスとの関係が書かれていない |
| 4 | 受け手と使う場面が具体的。既存サービスとの関係と、誤解を防ぐ表示が明記されている |
| 5 | 4に加え、受け手（自治体・住民団体等）の関与や利用の見込みが根拠付きで示されている |

## 完成度（手法の実装・実施の程度）
| 点 | 観点 |
|---|---|
| 1 | 約束の実現手段が書かれていない |
| 2 | 本応募までの約束が実装の見込みを大きく超える（実体がない状態で経路探索相当を約束する等） |
| 3 | 約束は実装可能な範囲だが、試作・見本が本応募時点で見込めない／範囲の書き方があいまい |
| 4 | 約束が実装可能な範囲に絞られ、必達と努力目標が区別されている。対象範囲（地域）が明記されている |
| 5 | 4に加え、動く版や見本が既にあり、URL等で確認できる |

## 挑戦度（新規性、アウトプットの広がり、持続性、関係者の多様性）
| 点 | 観点 |
|---|---|
| 1 | 中核が既存の公的サービスと同じ |
| 2 | 新しさの説明がない、または既存との違いが小さい |
| 3 | 既存との違いが1点明確。広がり・持続性・関係者のうち1つに触れている |
| 4 | 既存を土台として明示した上で違いが明確。広がり・持続性・関係者のうち2つ以上に触れている |
| 5 | 4に加え、関係者の参加や継続の仕組みが根拠付きで示されている |
