# 配電線 樹木リスク台帳（提案α コンセプトデモ）

衛星データ活用アワード2026–2027 提案α「倒木で止まる配電を、衛星で先に見つける」の、流れを確かめるための静的Webアプリ。提案B（app/proposal-b）と並べて比較するための追加物で、現行ファイルは変更していない。

## 実データか架空か（先に読む）
| 画面 | 内容 | 区分 |
|---|---|---|
| ①〜④ 優先地図・現地確認の計画・記録・点数の見直し | 配電線14区間、樹高、変化、停電想定戸数、重要施設、点数、現地確認の記録 | **すべて架空**（data/sample.js。画面のバナー・名称・CSV に「架空」と明示） |
| ⑤ 実データ体験 | Meta・WRI 高解像度樹高マップ（東京都青梅市周辺 約2.3km四方）を実際に取得し、その上に利用者が引く**仮の線**の周囲の樹高を集計 | **樹高は実データ**。線は実在の配電線ではない（配電線の位置は事業者データで未入手） |

実データ版の対象を「配電線に沿った樹高」にできなかった理由: 配電線・電柱の位置が公開されておらず、OpenStreetMap の取得は今回の環境で応答がなく確認できなかった。実在しない線を実在の地図に載せて見せることは避けた。

## 流れ
1. 優先地図: 区間ごとの点数（衛星・公開データ由来と事業者データ由来を分けて表示）。事業者データを重ねない場合の順位（衛星のみ）を併記し、重ねる効果が見える。
2. 現地確認の計画: 上位N区間を高精度測定（航空LiDAR・ドローン）と現地確認に回す対象にし、営業所からの回り順を出す。事業者・市町村・府県が共有する協議用の区間表（実施主体・費用負担は空欄）をCSVで書き出す。
3. 現地確認の記録（localStorage、CSV書き出し）。
4. 点数の見直し: 結果を区分ごとに集計し、重みを人が手で調整。順位に反映。
5. 実データ体験: 地図をクリックして仮の線を引く（「例の線」ボタンもある）。線の両側（10/15/25m）のセルの最大・90%値・高木率を、100m区間ごとに表示。

## 起動方法
サーバー側処理・APIキーは不要（背景は地理院タイルをブラウザが直接GET）。
```
cd contests/satellite-2026/app/proposal-alpha
python3 -m http.server 8873 --bind 127.0.0.1
# http://127.0.0.1:8873/
```

## 衛星で言えること／言えないこと
- 言える: 数百m単位の区間で、高い樹木が線の近くに多い所を相対的に絞る。台風・豪雨後に変化の大きい区間を絞る。
- 言えない（画面にも表示）: 個々の樹木と電線の離隔距離、倒木の予知、事故の削減効果、樹種の判別、巡視・航空LiDAR・ドローンの代替。
- 樹高マップの誤差: 論文は平均絶対誤差2.8m（カリフォルニア州・サンパウロ州）。日本での検証値は未確認。撮影は冬季で、現在の樹高ではない。

## 限界（未実装・未接続）
- Sentinel-2 の変化検出は未実装。①〜④の「変化」は架空の値。
- 数値標高モデルによる地形も①〜④では架空の値。点数のしきい値と重みは仮置きで根拠がない。事業者データ由来の項目（停電想定戸数、重要施設、過去の倒木、伐採履歴）は事業者から受け取る前提で、架空の値。
- 回り順は直線距離の最近傍法で、道路・立入可否は考慮しない。
- 記録はブラウザ内のみ。共有・認証・監査ログなし。個人情報は入れない運用。
- ⑤の線は利用者が引く仮の線で、線と樹木の離隔距離は出せない。90%値は元の約1m格子を集約した値。
- 実運用に必要な事業者との合意（データ提供、影響範囲の取り扱い）は未取得。
