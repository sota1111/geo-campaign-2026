# 不動産情報活用部門 本人加筆ガイド（R2 相続土地・空き家の出口診断）

目的: 生成AIの出力そのままと見なされないよう、本人の経験・判断を入れる。この案は本人の体験を最も足しやすい。
【本人加筆: …】の括弧書き全体（【】含む）を、本人の文に置き換える。括弧書きの長さ程度に収めると上限内に収まる。置換後に必ず `python3 contests/ichibiz-2026/check_limits_divisions.py` を実行する。
相続・空き家の経験がない場合は、無理に作らず、取材した相手（家族・知人・自治体窓口・司法書士など）の話を「聞いた話」として書く。実際にない経験は書かない。

| 場所 | 問いかけ | 書き方のヒント |
|---|---|---|
| problem.md 1段落目末 | 相続・実家・空き家で、自分や身近な人は何に悩んだか | 「誰が・いつ・何に」を1〜2文。個人が特定されない範囲で |
| service.md 末尾 | 自分ならどの画面で何を知りたかったか。この1枚のシートに最初に見たい項目は | 具体的な項目名を1つ。サービスの設計判断として書く |
| background.md 冒頭 | 相続・空き家・実家の処分で経験したこと | 最も重要な加筆。時期・立場・困りごと |
| background.md 2か所目 | 判断に必要な情報は公開されていたのに分からなかったのは、具体的にどの点か | 実際に困った点に書き換える。違うなら削除 |
| background.md 末尾 | 誰に相談したか。相談前にあれば助かった情報は何か | 相談先（役所、司法書士、不動産会社、親族）と、足りなかった情報 |

提出前の確認（要項・約款）
- reinfolib.md: APIコードと内容の対応を公式API仕様で確認する（sources.md参照）。字数は未確認で400字以内を目安にしている。応募フォームで上限が分かったら、検査スクリプトの reinfolib.md の値を直す。
- 出典表記「国土交通省 不動産情報ライブラリ」とURL、加工の明記、免責、サービス名に名称を使わない、の4点を本文・補足資料で守る。サービス名は未決定。付ける場合は「不動産情報ライブラリ」を含めない。
- 査定に見える表現（金額の推定、売却・購入の推奨）が入っていないか。
- 相続登記の義務化・国庫帰属制度の日付を法務省の公式ページで確認する。
