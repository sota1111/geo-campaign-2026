# 大規模修繕プラットフォーム（イチBiz 2026 新案・デモ）

対象: ichibiz-2026（新案。部門は総司令官が選ぶ。提出文は作っていない）。2026-11-22 工兵。
総司令官の指示: 「マンション大規模修繕価格の適正化。地図情報、建物情報、SLAMデータを用いて、類似マンションの大規模修繕情報を探し、適正料金を推定する。口コミや価格等の情報を基に発注先を検討できる」。
根拠の調査: `reports/intel/ichibiz-2026-repair-platform-20261122.md`（情報部）。

## 何を作ったか（実データでできる範囲に絞った）
情報部の調査で、実データで作れるのは「公的調査の分布の中で、自分の条件と見積がどの位置か」までと分かっている。個別の類似事例と、適正料金の一点の推定は、根拠がなく作らない。そのため次の形にした。

| 指示 | この画面での形 | 種別 |
|---|---|---|
| 地図情報・建物情報 | 墨田区の PLATEAU の建物を地図に表示。建物を押すと、高さ・外周・推定階数・推定延床・外壁面積の概算 | 実データ＋推定 |
| 適正料金を推定 | 「適正料金」は出さない。国交省調査の分布から、**目安の範囲**（下位25%値〜上位25%値）と、**見積の分布での位置**（中央値より◯%高い／上位25%に入る） | 実データ＋計算 |
| 類似マンションの修繕情報 | 個別事例の公開データはない。**規模の近い実在のマンション**（OpenStreetMap で共同住宅とされたもの）を、名前（あるものだけ）・町丁目・規模・上空写真つきの小さなカードで並べ、地図の番号と対応させる。**実在の建物に修繕費・実績・口コミは結び付けない**（各カードは「修繕実績: 未登録（公開データなし）」）。修繕事例は、利用者が自分の実績を登録する受け皿で、デモは「架空のデモ事例（実在の建物ではありません）」の別枠 | 実データ＋推定＋利用者入力＋架空 |
| SLAM データ | PLY・LAS・XYZ の点群をブラウザの中で読み、外周・高さ・外壁面積を概算。見本は合成 | 利用者入力＋合成 |
| 口コミ・価格で発注先を検討 | 公的情報へのリンク、見積比較のチェック項目、口コミの自己投稿の受け皿（デモは架空）。並びを操作できない設計 | 実データ（リンク）＋架空 |

## 使ったデータと範囲
- **PLATEAU 建物**: 3D都市モデル（Project PLATEAU）東京都23区（2022年度）CityGML（v2）の建築物モデル（LOD1）。国土交通省。G空間情報センター https://www.geospatial.jp/ckan/dataset/plateau-tokyo23ku-2022 。ライセンスは PLATEAU Site Policy「3．著作権について」（https://www.mlit.go.jp/plateau/site-policy/ 、商用利用を含め無償）。**範囲は墨田区（13107）全域の 46,386 棟**。取得は HTTP Range の GET のみ（`tools/remotezip.py`。約5GB の ZIP の全体は取らず、墨田区に重なる56メッシュだけ読む）。
- **国交省調査**: 国土交通省「令和3年度マンション大規模修繕工事に関する実態調査」報告書 https://www.mlit.go.jp/jutakukentiku/house/content/001619430.pdf と概要 https://www.mlit.go.jp/jutakukentiku/house/content/001477900.pdf 。200社・工事事例818件の集計。図表の数値を手で転記して `web/data/mlit-survey.json` に頁つきで同梱（報告書 p.13 総額、p.14 戸あたり、p.15 ㎡あたり、概要 p.1 内訳・修繕周期、報告書 p.56 発注方法）。工事金額は、共通仮設費と消費税を含まない（報告書 p.4、概要 p.1）。**この調査の二次利用条件は要確認**（情報部 R-2。PDF に表記がなく、確認できていない）。画面と本書に明記し、出典・加工（転記・計算）を表示している。
- **地図**: 国土地理院 地理院タイル（淡色地図）。
- **共同住宅・名称（2026-11-22 追加）**: © OpenStreetMap contributors（ODbL 1.0。https://www.openstreetmap.org/copyright ）。Overpass API の GET（`tools/fetch_osm.py`）で、墨田区の `building=apartments|residential|dormitory` の建物 6,293 件を取り、中心点が PLATEAU の候補建物（3,581 棟）の外形の内側に入るものだけを突き合わせた。**結果は 543 棟（apartments 468・residential 74・dormitory 1）、うち OSM に名前（name タグ）があるのは 81 棟**。1つの PLATEAU 建物に複数の OSM 建物が当たったときは名前のあるほうを残す。結果は `web/data/osm.json`（PLATEAU の建物ID・種別・名称）。名前は OSM にあるものだけで、補わない。名前の無い 462 棟は「名称不明」＋町丁目。PLATEAU の名称（124 棟）は学校・病院・郵便局などの公共施設で、共同住宅ではないので使わない。OSM の登録は不完全なので、実在のマンションの全部ではない（墨田区で地図に出る規模の建物 3,581 棟のうち 543 棟）。
- **上空写真**: 国土地理院 シームレス空中写真（地理院タイル `seamlessphoto`、https://maps.gsi.go.jp/development/ichiran.html 、出典表示）。カードごとに、建物の位置を中心に z18 のタイル 4 枚から 132×99px を切り出し、PLATEAU の外形線（黄）を重ねる。ブラウザが表示時にタイルを GET するだけで、画像は同梱しない。
- **外観写真**: Wikimedia Commons の CC BY / CC BY-SA / CC0 等で、作者・ライセンスを表示できるものだけに限る設計（`web/data/photos.json`、`tools/fetch_commons.py`）。**現在の採用は 0 棟**。名前のある 81 棟の半径 60m にある画像（座標つき）を探して候補 30 枚を得たが、いずれもスカイツリー・飲食店・駅など別のもので、その建物を写したものは無かった（目で確認）。見つからなかった建物に、近くの別の写真を付けることはしない。Google ストリートビュー等、規約上使えないものは使わない。
- 不動産情報ライブラリは使っていない。

| 屋根外形の面積（buildingRoofEdgeArea） | 43,226 | 93.2% |
| 建物名称 | 124 | 0.3% |
| **建築年** | **0** | **0%** |
| **地上階数** | **0** | **0%** |
| **延床面積** | **0** | **0%** |
| **用途** | **0** | **0%** |

墨田区以外でも同じかを、23区の全 671 メッシュから等間隔に 34 メッシュ（84,395 棟）を抜いて調べた（`tools/peek.py --every=20`、2026-11-22）。建築年・階数・延床・用途・構造は1棟も入っていなかった。2020年度版の CityGML（v3_2、v4_2）でも、同じメッシュで同じだった。
このため次の扱いにした。
- 「共同住宅らしい建物」は、**用途ではなく規模**で選んだ（高さ12m以上、かつ屋根外形の面積150㎡以上。墨田区で 3,581 棟）。共同住宅とは限らない（事務所・工場・学校なども入る）。画面の地図の注記に常に書いている。
- 階数は「高さ ÷ 階高」の**推定**。階高は仮の 3.0m（画面で変えられる）。根拠のある値ではなく、仮置き。
- 延床は「屋根外形の面積 × 推定階数」の**推定**（参考値）。
- 築年は PLATEAU に無いので、利用者入力。「似た建物」は築年で選べない。
- 戸数は PLATEAU に属性の定義が見つからなかったので、利用者入力。

## 外壁面積の概算（参考値）
外周（屋根外形の座標から計算）× 高さ（計測高さ）。開口部・バルコニー・パラペット・隣棟との接面は考えない。LOD1 は単純な形なので、実際の外壁との誤差は**検証していない**。

## 修繕費の目安と見積の位置
- 目安の範囲 = 国交省調査（工事回数別）の下位25%値〜上位25%値 × 戸数（戸あたり）、同 × 延床（㎡あたり）。中央値も併記。
- 見積の位置 = 見積（税込なら 10% を除く）を戸数・延床で割り、調査の四分位と比べる。「中央値より◯%高い／低い」と、「上位25%に入る／中央値と上位25%値の間／下位25%値と中央値の間／下位25%に入る」。四分位の3点しか公表されていないので、外側の割合（上位何%）は推定しない。
- 総額の位置は、規模の違いを考えない参考として併記。
- 内訳比率（概要 p.1）と、総額に対する外壁関係・防水関係の比率（掛け算の計算）を表示。
- 築年からの工事回数の見当: 回数別の平均修繕周期（1回目15.6年、2回目14.0年、3回目以上12.9年。概要 p.1）を足し上げた築年に最も近い回。計算で出した見当であり、回数は利用者が選ぶ。
- 表現: 「適正料金」を一点で断定しない（景品表示法の不実証広告規制に当たる懸念。情報部の調査）。「目安」「分布での位置」「参考」と書き、**「適正な金額であることを保証しません」**と画面に常に出す。「査定」は使わない（テストで検査）。

## 画面の構成（2026-11-22 評価ループ第1回で改修）
広い画面（1513×784）は縦スクロールなし。「目安・見積」タブはパネル内スクロールもなし。狭い画面（390×844）は縦に積み（地図が先）、画面下に要約バー（目安の範囲・見積の位置）を固定。タブは1段。
- 地図: 「例の建物を選ぶ」、地区（丁目をまとめた町名）・規模で絞る、階高の仮定。選んだ建物に「選択中」の吹き出し。
- タブ「目安・見積」: 先頭に結果（目安の範囲・範囲バーと見積の印・結論の1行）。その下に戸数・見積・税。延床・築年・階数・工事回数は「条件を変える」に折りたたみ。似た規模の建物の上位3棟と、その延床での目安。国交省調査の表・内訳は「根拠」に折りたたみ。
  - 建物を押すと、延床（推定）と戸数（推定: 延床÷70㎡の仮定）を入れ、すぐに目安の範囲を出す。推定の欄には「推定」の印。利用者が入れた値が優先。
  - 推定40階超・延床50,000㎡超は「マンションの規模ではない可能性が高い」として目安を出さない。延床800㎡未満は警告。いずれも設計上の線引きで、根拠のある統計値ではない。
  - 1戸あたり延床が30〜150㎡の外なら「戸数と延床が合っていません」と出し、延床あたりの範囲と位置は出さない。主指標は戸あたり（戸数が無ければ延床あたり）。総額の位置は「根拠」の中の参考に格下げ。中央値の10倍を超える比率は「桁を確認」。
- タブ「似た建物」: OSM で共同住宅とされた 543 棟のうち、推定階数±2階で、延床・高さ・外周・距離が近い 6 棟を小さなカードで並べる（同じ町・同じ規模の重複はまとめる。名前の分かる建物は規模の比で約16%の差までは先に並べる＝並びへのわずかな優遇。「規模が近い」「距離」で並べ替え、「地図に全部映す」で地図を引く）。カード＝番号（地図の緑の番号と同じ。押すとその建物を選ぶ）・上空写真・名前または「名称不明」・町丁目・推定階数・延床（推定）・高さ・距離・写真の種類（上空／外観）・「修繕実績: 未登録（公開データなし）」。**金額・口コミ・評価の数値は出さない**（旧版の「延床×㎡あたりの目安」の試算列は、実在の建物に金額が付くので廃止）。住戸・居住者の情報は扱わず、住所は町丁目まで。修繕事例（見本）は別枠で「架空のデモ事例（実在の建物ではありません）」。
- タブ「点群」: 見本の読み込みを先頭に。限界は1行（詳細は折りたたみ）。結果は外壁面積と、点群・地図の外壁面積それぞれで「見積の外壁関係（調査の平均比率で配分）÷面積」の単価の表。
- タブ「発注先比較」: 見積を3社分（会社名・金額）入れ、各社の目安の中の位置と口コミ件数（利害関係ありの件数）を表に、各社の印を同じ範囲バーに並べる。口コミ（架空）・チェック項目・公的リンクは折りたたみ。
- タブ「出典」: 出典・加工・責任、限界、付与率（折りたたみ）、プライバシー。
- 免責は画面上部の1か所（「出典」タブの限界にも記載）。

## 実データと架空・合成の区別
バッジを画面の上部に常に出し、各項目にも付ける: 「実データ」（緑。公的データそのもの）、「推定」（青。計算した参考値）、「利用者入力」（灰）、「架空・合成」（橙の斜線）。デモの事例3件・口コミ4件は、1件ごとに「架空」の印と破線の枠、一覧の上に「すべて架空のデモ」の帯。見本の点群は「合成データ（実在の建物ではありません）」。数値は説明用の架空の値で、根拠はない。

## SLAM（点群）の限界
スマホの LiDAR の検出範囲は一般に1〜5m程度（電子情報通信学会 FIT2025 I-015、メーカー資料の5mという数値。情報部の調査から。原文は未確認）。地上から高層の外壁全体は測れず、測れるのは低層部・共用部・屋上・バルコニー程度。この画面の値は読み込めた範囲だけのもの。凸包の外周は、壁1面だけの点群では往復で数えるので、細長い点群は壁の長さを半分とみなす。形式は PLY（ASCII・バイナリ）・LAS（無圧縮）・XYZ。LAZ（圧縮）は読めない（WASM が要る）。点群には居住者や住戸内部が写りうるので、ブラウザの中だけで扱い、送信・保存しない。

## 口コミの並びを操作できない設計（理由）
ステマ規制（令和5年内閣府告示第19号、令和5年10月1日施行）は、事業者の表示であることが分かりにくい表示を景品表示法の不当表示とする。事業者が口コミの表示内容の決定に関与すれば、事業者の表示になる（情報部の調査。確定版の運用基準は未照合＝R-7）。また公取委の 2026-09-28 の公表は、施工会社が請負金額の一定割合を設計コンサルタントに支払っていた事実に触れている。紹介料や広告料を受けつつ口コミの並び・抽出に関与するモデルは、これらの論点になりうる（情報部の推測）。そこで次の設計にした。
- 並びは投稿日の新しい順だけ。評価・会社・利害関係の申告では並べ替えず、平均点も出さない（テストで、評価・会社名・申告を書き換えても並びが同じことを検査）。会社名の絞り込みは並びを変えない。
- 会社が並び・表示・抽出に関与する経路を作らない。広告枠・紹介料なし。
- 投稿時に利害関係の有無を必須にし、「あり」は表示に残す。
- 他の口コミサイトの転載・収集はしない（エキテンは規約で収集を禁止。他は未確認）。

ビジネス部門（11/30 20:00）は、実現可能性と持続性が見られ、事業化の課題の記入欄もある。この案の収益を施工会社からの紹介料に頼る形にすると、公取委が問題視した構図に近づくので、収益モデルの説明が難しい（推測）。アイデア部門（12/10 20:00、実装不要）は、デモとして最も素直に合う。不動産情報活用部門（12/10 20:00）は、不動産情報ライブラリの活用が趣旨だが、この案は修繕費の分布に国交省調査を使い、ライブラリは使っていないので、「活用する不動産情報ライブラリの情報」の記入欄の説明が難しい（情報部の推測。審査での評価は未知）。また、同じ不動産部門の 23区、値段の年表（realestate-timeline）とは別の題材だが、複数案は互いに不利になりうる。部門は総司令官が選ぶ。
