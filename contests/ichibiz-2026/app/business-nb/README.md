# 使用済み太陽光パネルの回収圏計画（イチBizアワード2026 ビジネス部門・新案NB・最小デモ）

現行案（バス路線の見直し案の比較、`../business/`）と**入れ替えず並べて比べる**ための追加案。提出文は `contests/ichibiz-2026/submission/business-nb/`。

資源エネルギー庁の再エネ事業計画認定情報（京都府ファイル）の太陽光設備を地図にし、運転開始などから廃棄時期を**仮説で**推定し、リサイクル施設（京都府の公表3社＋京都北部の拠点〔推定〕＋府外2社）からの距離と回収圏の内外を示す静的Webアプリ。拠点を1か所足した場合の試算、市区町村別の表、年別の図、CSV書き出しがある。サーバー・APIキー不要、外部への送信なし。

## 実データか架空か
**実データ**（架空サンプルへの切替は不要だった）。理由: 認定情報は公表サイトからxlsxで取得でき、「ご利用上の注意」で商用利用可（出典記載と加工した旨の明記が条件）と確認した。

- 認定情報: 京都府ファイル、2026年9月30日時点（10月14日公表）、2026-11-12 取得。太陽光3,116件。うち運転開始前22件と位置不明6件を除く**3,088件・509.3 MW**を使用。
- 位置: 設備所在地（代表地番）を国土地理院の住所検索APIで変換。**町字の代表点 2,954件、町字が引けず市区町村の代表点 134件（約4.3%）**（精度が粗い。ポップアップと CSV の前提に明記）。2026-11-13 の修正前は 2,040件と1,048件（約34%）だった（下の「W1: 郡部の位置が全件外れていた」）。
- 事業者名・代表者名・事業者住所・電話・設備IDは取り込んでいない（`tests/test_app.py` で検査）。
- リサイクル施設: 6か所（下の「リサイクル施設と出典」）。大阪府ページは403で取得できず、デモの公式の出典にしていない。

## 起動

```
cd contests/ichibiz-2026/app/business-nb
python3 -m http.server 8831 --bind 127.0.0.1 --directory web   # http://127.0.0.1:8831/
```

`web/` をそのまま静的ホスティングできる。地図タイル（地理院）と MapLibre（unpkg、SRI付き）はブラウザがインターネットから取得する。取得できなくても表と CSV は動く。

## 画面の流れ

1. 仮説を置く: 廃棄時期の置き方（調達期間の終了時／運転開始＋25・30・35年）、対象年（2035〜2060年まで）、使う施設（府外の施設も含める／京都府内のみ）、回収圏の半径（10〜50km）。選んだ組で対象が0件になる場合は、0件の理由（その仮説で最も早い設備の推定年）を表示し、「圏外0%」とは出さない
2. 回収圏の中か外か: 対象年までに出ると推定した設備の件数・出力、圏外の割合、施設別の表、年別の積み上げ図
3. 拠点を足すと？: 地図をクリックして置く／距離の合計が最も減る町字を探す → 圏外と平均距離の前後
4. 市区町村別の表、CSV書き出し、出典・前提・限界

## 何を計算しているか・できないこと

- **廃棄時期は仮説。** 「運転開始報告年月の年＋N年」、または調達期間（FIT）終了年（データの列。空なら運転開始＋20年）。Nは利用者が選ぶ仮の値で、**年数の公的根拠は確認していない**。既定の25年は、京都府ページの「2030年代後半以降に顕著に増加」と大きくは食い違わない説明用の仮置きで、根拠ではない。
- 距離は**直線**（道路距離・運搬費・施設の受入能力・許可の範囲・パネルの種類は未考慮）。最寄りは直線で最も近い施設。
- 出力（kW、太陽電池の合計出力。空なら発電出力）のまま集計。**トン数への換算はしない**（根拠のある換算式を確認していないため）。政府・民間の排出量推計（年間最大50万トン程度、40万トン超）との照合もしていない。
- 元データに**出力20kW未満の太陽光は含まれない**（公表サイトの注記）。認定情報は失効した認定を含みうる。複数地番の設備は代表地番のみ。
- 候補拠点の探索は、対象年までの設備について出力×最寄りまでの距離の合計が最も減る町字（precision=町字のもの）を選ぶだけ。用地・許可・道路は見ていない。
- 事業性・市場規模・価格の数値は画面に載せていない。

## 情報部の報告との差（工兵が実ファイルで確認した点）
- 運転開始: 列「運転開始予定日」（申請時の見込み）のほかに「運転開始報告年月」（報告された年月）がある。デモは後者を使い、未報告22件は対象外にした。
- 20kW未満: 公表サイトのお知らせ本文に「太陽光20kW未満を除く」とある。
- 形式: CSVではなく xlsx（シート1=代表地番、シート2=全地番）。

`raw/`（取得したxlsx、約0.7MB）は .gitignore。`cache/geocode.json` は再現のため含める。他県を足す場合は `KYOTO_FILE` と施設リストの差し替えが要る（今回は未対応）。

## 2026-11-13 アグレッサー指摘（W1〜W3・画面の壊れ方）への修正

### W1: 郡部の位置が全件外れていた（原因の訂正）
- 以前の README と画面は、位置が粗い理由を「町字が引けなかったため」としていたが、**原因はデータ生成の不具合**だった。地理院の住所検索APIは、郡部の町字の title を郡を省いて返す（q=京都府与謝郡与謝野町三河内 → title=京都府与謝野町三河内。2026-11-13 に実APIで確認）。`build_data.py` の `geocode()` はクエリ（郡あり）で title が始まるかを見ていたため、郡部の町字が全部不一致になっていた。
- 直し方: クエリと title の両方から「○○郡」を取り除いて比べる（`strip_gun`）。title に「字」「大字」が入る町（例: 京都府大山崎町字円明寺佃）もあるので、比較では「字」も取り除く。
- 結果（地理院APIを再取得、`--offline` でも同じ結果を再現確認）: 市区町村の代表点 **1,048件（33.9%）→ 134件（4.3%）**、町字の代表点 2,040件 → 2,954件。残る134件は、APIが町字を返さない住所（例: 亀岡市・宇治田原町・精華町の一部の小さな字）。1点に重なる設備の最大は589件（京丹波町の役場付近）→ 131件（京丹波町の1町字。町字の代表点で、これ以上は分けられない）。
- 「約34%」「1,048件」を書いていた README・画面（`limits()` は件数を実データから出す）を更新した。**提出文（submission/business-nb/）は触っていない**ので、提出文に旧数字があれば差し替えが要る。
- 圏外の割合（＋25年・2045年まで・20km）は、W3の施設追加と合わせて次のとおり変わった。直線距離のみ・処理能力は見ていない。

| 京都府公表の3社のみ（修正前） | 61.7% | 30.3% |
| 3社＋京都北部の拠点（推定） | 31.0% | 2.6% |
| 上記＋府外2社（既定） | 30.1% | 2.6% |

見出しの「圏外6割」は、北部の拠点が地図に無いことによる部分が大きかった（北部の拠点の所在地が推定である点に注意）。

### W2: 対象0件の組
- 画面で選べる「仮説×対象年」20通りのうち6通り（＋25年/2035、＋30年/2035・2040、＋35年/2035・2040・2045）は、運転開始報告が2013年以降のため対象が0件になる。選べるままにして、**0件の理由を画面に出す**ようにした（「その仮説では最も早い設備でも○年で、2035年までには出ない。圏外の割合は計算できない（0%ではない）」）。0件のとき、候補探索のボタンは押せなくなり、候補地も置かない。CSVにも注意行を入れる。

### 画面の壊れ方
- 対象0件: 理由を表示。候補探索は押せない／置かない（W2）。
- 施設0件: JSの内部エラー文ではなく「リサイクル施設のデータが入っていない…」と表示。`analyze` は施設が空でも落ちず、すべて圏外として扱い距離は出さない。
