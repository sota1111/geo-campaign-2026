# 使用済み太陽光パネルの回収圏計画（イチBizアワード2026 ビジネス部門・新案NB・最小デモ）

現行案（バス路線の見直し案の比較、`../business/`）と**入れ替えず並べて比べる**ための追加案。提出文は `contests/ichibiz-2026/submission/business-nb/`。

資源エネルギー庁の再エネ事業計画認定情報（京都府ファイル）の太陽光設備を地図にし、運転開始などから廃棄時期を**仮説で**推定し、京都府が公表するリサイクル施設3社からの距離と回収圏の内外を示す静的Webアプリ。拠点を1か所足した場合の試算、市区町村別の表、年別の図、CSV書き出しがある。サーバー・APIキー不要、外部への送信なし。

## 実データか架空か
**実データ**（架空サンプルへの切替は不要だった）。理由: 認定情報は公表サイトからxlsxで取得でき、「ご利用上の注意」で商用利用可（出典記載と加工した旨の明記が条件）と確認した。

- 認定情報: 京都府ファイル、2026年9月30日時点（10月14日公表）、2026-11-12 取得。太陽光3,116件。うち運転開始前22件と位置不明6件を除く**3,088件・509.3 MW**を使用。
- 位置: 設備所在地（代表地番）を国土地理院の住所検索APIで変換。**町字の代表点 2,040件、町字が引けず市区町村の代表点 1,048件**（約34%は精度が粗い。ポップアップと CSV の前提に明記）。
- 事業者名・代表者名・事業者住所・電話・設備IDは取り込んでいない（`tests/test_app.py` で検査）。
- リサイクル施設: 京都府「太陽光パネルの3R・適正処理について」（更新2026-03-05）の3社（近畿電電輸送、浜田、京都環境保全公社）。所在地は同ページの記載を地理院APIで位置に変換。大阪府ページは403で取得できず（情報部の確認では浜田1社で施設は京都府八幡市）、デモに含めていない。

## 起動

```
cd contests/ichibiz-2026/app/business-nb
python3 -m http.server 8831 --bind 127.0.0.1 --directory web   # http://127.0.0.1:8831/
```

`web/` をそのまま静的ホスティングできる。地図タイル（地理院）と MapLibre（unpkg、SRI付き）はブラウザがインターネットから取得する。取得できなくても表と CSV は動く。

## 画面の流れ

1. 仮説を置く: 廃棄時期の置き方（調達期間の終了時／運転開始＋25・30・35年）、対象年（2035〜2060年まで）、回収圏の半径（10〜50km）
2. 回収圏の中か外か: 対象年までに出ると推定した設備の件数・出力、圏外の割合、施設別の表、年別の積み上げ図
3. 拠点を足すと？: 地図をクリックして置く／距離の合計が最も減る町字を探す → 圏外と平均距離の前後
4. 市区町村別の表、CSV書き出し、出典・前提・限界

## 何を計算しているか・できないこと

- **廃棄時期は仮説。** 「運転開始報告年月の年＋N年」、または調達期間（FIT）終了年（データの列。空なら運転開始＋20年）。Nは利用者が選ぶ仮の値で、**年数の公的根拠は確認していない**。既定の25年は、京都府ページの「2030年代後半以降に顕著に増加」と大きくは食い違わない説明用の仮置きで、根拠ではない。
- 距離は**直線**（道路距離・運搬費・施設の受入能力・許可の範囲・パネルの種類は未考慮）。最寄りは直線で最も近い施設。
- 出力（kW、太陽電池の合計出力。空なら発電出力）のまま集計。**トン数への換算はしない**（根拠のある換算式を確認していないため）。政府・民間の排出量推計（年間最大50万トン程度、40万トン超）との照合もしていない。
- 元データに**出力20kW未満の太陽光は含まれない**（公表サイトの注記）。認定情報は失効した認定を含みうる。複数地番の設備は代表地番のみ。
- 候補拠点の探索は、対象年までの設備について出力×最寄りまでの距離の合計が最も減る町字（precision=町字のもの）を選ぶだけ。用地・許可・道路は見ていない。
- 事業性・市場規模・価格の数値は画面に載せていない。

## 情報部の報告との差（工兵が実ファイルで確認した点）
- 運転開始: 列「運転開始予定日」（申請時の見込み）のほかに「運転開始報告年月」（報告された年月）がある。デモは後者を使い、未報告22件は対象外にした。
- 20kW未満: 公表サイトのお知らせ本文に「太陽光20kW未満を除く」とある。
- 形式: CSVではなく xlsx（シート1=代表地番、シート2=全地番）。

## データ生成

```
python3 build_data.py            # raw/kyoto.xlsx が無ければ公表サイトから取得。住所の変換に約15分（地理院API、結果は cache/geocode.json）
python3 build_data.py --offline  # raw/ と cache/ だけで同じ web/data/ を再生成（再現確認済み）
```

`raw/`（取得したxlsx、約0.7MB）は .gitignore。`cache/geocode.json` は再現のため含める。他県を足す場合は `KYOTO_FILE` と施設リストの差し替えが要る（今回は未対応）。

## 出典・ライセンス

| データ | 出典 | 条件 |
|---|---|---|
| 認定情報 | 再生可能エネルギー電子申請サイト「事業計画認定情報 公表用ウェブサイト」京都府ファイル https://www.fit-portal.go.jp/PublicInfo を加工して作成（太陽光のみ抽出、住所を位置に変換、廃棄時期を仮説で推定、距離を計算） | 利用ルール https://www.fit-portal.go.jp/Terms （商用可、出典記載・加工の明記、国が作成したかのような公表の禁止）。画面とCSVに記載済み |
| 位置の変換 | 国土地理院 住所検索API | 町字の代表点 |
| リサイクル施設 | 京都府 https://www.pref.kyoto.jp/sanpai/pvpanerutekiseisyori.html | 事業者名・所在地・URLのみ使用 |
| 背景地図 | 地理院タイル（淡色地図） | 国土地理院の利用規約 |
| 描画 | MapLibre GL JS 4.7.1 | BSD-3-Clause |

利用規約は変わりうる。公開前に最新の条件を確認すること。認定情報は毎月更新される。

## テスト

```
python3 -m unittest discover -s tests          # 11件（node が必要）
node tests/ui_check.mjs http://127.0.0.1:8831/ screenshots   # 画面確認（要 google-chrome、サーバー起動後）
```

- `lib_test.js`: 距離、廃棄時期の置き方、集計（圏外・施設別・年別・市区町村別）、単調性（回収圏を広げれば圏外が減る・対象年を前倒しすれば対象が減る）、拠点追加で圏外が減る、候補探索、CSVエスケープ、実データの範囲・型。
- `test_app.py`: 住所分解・日付変換、xlsx読み取り、データの件数整合・個人情報の列が無いこと・施設3件、POST・外部送信が無いこと、画面に仮説・直線・20kW未満・実データの表示があること。
- `ui_check.mjs`: デスクトップ・スマホ幅で一通り操作（条件変更、候補探索、CSV、出典）。コンソールエラーなし、横スクロールなし。結果: 2026-11-13 に OK。
