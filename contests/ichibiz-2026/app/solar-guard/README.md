# 太陽光発電所の盗難対策マップ（イチBizアワード2026・新案・最小デモ・茨城県）

新案NB（使用済みパネルの回収圏計画、`../business-nb/`）の構成を踏襲した別の案。入れ替えず並べて比べる。提出文は未作成（部門は総司令官が決める。ビジネス 11/30、アイデア 12/10）。

銅線ケーブル等の金属盗から太陽光発電所を守る対策の優先順位を、**公開データから作る「目安」**で考える静的Webアプリ。公開するのは約5kmメッシュと市町村の**集計だけ**で、個別設備の順位・一覧は出さない。メッシュも**5段階の帯**だけで、連続のスコアや順位は画面・CSV・公開 JSON のどこにも出さない。事業者が自分の設備の位置と対策を入れる自己診断は、ブラウザ内だけで計算する。サーバー・APIキー不要。

## NB との違い（顧客・課題・成果指標）

| | NB 回収圏計画 | 本案 盗難対策マップ |
|---|---|---|
| 顧客候補 | 使用済みパネルの回収・リサイクル事業者、自治体 | 発電事業者、O&M事業者、保険会社、自治体・警察の防犯担当 |
| 解く課題 | 将来の大量廃棄に対する回収網の空白 | 銅線ケーブル等の金属盗への対策の優先順位づけ |
| 成果指標（案） | 回収圏外の設備の割合（直線距離・仮説） | 事業者が未実施の対策に気づけること、集計メッシュ・市町村の目安（被害の予測ではない） |
| 対象地域 | 京都府 | 茨城県（盗難が多い。情報部: 京都府は太陽光の被害が少ない） |
| 位置 | 地理院API（町字の代表点） | e-Stat 小地域の名称との突き合わせ（外部問い合わせなし） |
| 出し方 | 設備の点を地図に出す | 設備は出さず、集計（約5km・市町村）のみ。メッシュは5段階の帯だけ。少ない集計は隠す |

成果指標は画面が出す値ではなく、提出文で検討する案。実効果の数値は何も主張していない。

## 実データか架空か
**実データ**。認定情報（茨城県ファイル、2026-10-31時点、取得 2026-11-13）の太陽光 **29,611件**のうち、運転開始報告済み **29,187件**（運転開始前424件を除く）を使用。出力は「発電出力（kW）」。
- 町字名を e-Stat 小地域（国勢調査2020）の名称と突き合わせて代表点を得た: 町字名が一致 **26,575件**、大字名で始まる小地域の代表点の平均 **2,075件**、対応づけられず市町村の集計のみ **537件（1.8%）**。
- 町字の面積は中央値 3.1km²、90%点 7.9km²で、1kmメッシュより粗い。このため公開の集計メッシュは1kmメッシュ×5＝約5km（東西約5.6km×南北約4.6km）にした。広い大字ではなお別のメッシュに数えられうる。
- 集計メッシュ: 設備のあるもの246。3件未満の11メッシュに加え、設備10件未満で50kW以上が1件以下の11メッシュ（大きな設備1件の出力が割り出せるため。下の「秘匿のしきい値」）を隠し、計22メッシュ（設備計84件）を除いた**224メッシュ**を出力。
- 人口: e-Stat 地域メッシュ統計（国勢調査2020、基準地域メッシュ約1km、第1次区画 5339 5340 5439 5440 5539 5540）14,257メッシュ。「*」（近隣に合算済み）は0。
- 事業者名・代表者名・事業者住所・電話・設備IDは取り込まない。ビルド時に集計して捨て、公開物に個別設備の位置は残らない（`tests/test_app.py` が原データ全件の設備ID・名称・電話が公開物に無いことを検査）。

## 起動

```

python3 -m http.server 8835 --bind 127.0.0.1 --directory web   # http://127.0.0.1:8835/
```

## 県警の被害実績との食い違い（隠さない）

県警 Metal News 第10号（令和8年9月末、暫定）の県内5地区別の太陽光の被害件数と、本アプリの目安を、地区ごとに並べた（画面の「公開の集計地図」と「盗難の実態」に同じ表を出す）。5地区の市町村の範囲は誌面にないので、茨城県の地域区分（県北・県央・鹿行・県南・県西）と同じと**推測**して、市町村の設備数を足した。

| 地区 | 県警の被害（件） | 設備数 | 設備1,000件あたり | 目安の地区平均の順（初期の重み、5地区中。1=最低） |
|---|---|---|---|---|
| 県南 | 164 | 7,884 | 20.8 | 2 |
| 県西 | 109 | 6,269 | 17.4 | 1 |
| 県北 | 39 | 2,282 | 17.1 | 5 |
| 県央 | 84 | 7,216 | 11.6 | 3 |
| 鹿行 | 38 | 5,536 | 6.9 | 4 |

- 初期の重みでの順位相関は **−0.60**（被害率の順と目安の順は、おおむね逆）。最初の版（人の少なさ・出力合計・低圧割合を等しい重み）は **−0.90** だった（アグレッサーの指摘）。
- 指標を1つずつ見ると、設備1件あたりの出力 +0.60、低圧割合 −0.90、人の少なさ −0.50。5点だけの比較なので、どれも有意とは言えない。
- この食い違いを画面（地図の読み方・凡例・ポップアップ・地区の表・出典の限界）と CSV に明記している。目安は「被害の起きやすさ」ではなく「被害額の大きさ（1件あたりの出力）と低圧設備の多さの目安」と読む。「当たる」「予測できる」とは主張しない。
- 県南・県西は千葉・埼玉に近い。アクセスや逃げやすさが効いている可能性があるが、検証していない（推測。入れるなら高速道路IC等のデータの利用条件の確認が要る）。

## 指標の見直し（何を、なぜ変えたか）

最初の版: 人の少なさ・出力合計・低圧割合を等しい重み（各1）で平均。見直し後の初期値: 設備1件あたりの出力 1、低圧割合 1、人の少なさ 0（参考）。

1. **人の少なさを主指標から外した（初期値0。スライダーでは使える）**。根拠は実績への当てはめではなく、指標そのものの妥当性: (a) 常住人口は、夜間・休日の人通りや見通しの代理として弱い（JPEA・REASP の言う「人目につきにくい立地」を測れていない）、(b) 海に面したメッシュは海の面積も含み、人口密度が低く出る（鹿行・県北の海側。県警の鹿行の被害が少ない実績と対応しない一因の可能性）、(c) 県境のメッシュは隣の県の人口を含む。
2. **出力合計を「設備1件あたりの出力」に変えた**。出力合計は設備数と同じ並びになっていた（位置の相関 0.77）。1件あたりにすると設備数との相関は −0.05。意味も「被害額の大きさ（高圧は被害額最大と想定、JPEA・REASP p.10）」に絞れる。市町村も同じ定義にそろえた（以前は面積あたりで、メッシュと定義が違った）。
3. **低圧割合は残した**。ただし県内ではどの地区でも約9割（88〜93%）で、地区のあいだの差が小さい。単独では県警の地区別と最も逆向き（−0.90）。外すと実績に合うように見えるが、実績に合わせて指標を選ぶことになるので、外していない。
4. **実績に合わせた重みの調整はしていない**。上の見直し（1・2）は指標の定義の問題で、実績の並びを見た後に行っているので、独立の検証ではない。見直し後も実績と一致せず、そのことを開示している。重みは利用者が変えられるが、5点で検証できないので、変えて「当たる」ことを示す使い方は想定しない。

## 目安の指標の定義
3つの代理指標を、県内の集計メッシュ224個（市町村は44）の中での相対位置（順位を0〜100にしたもの。同値は平均順位）に直し、利用者が決める重み（0〜5）で平均。**位置とスコアは内部の計算だけに使い、画面・CSV・公開 JSON には出さない**。出すのは五分位の5段階の帯（同じ帯に多数のメッシュが入る）だけ。
1. **設備1件あたりの出力**（初期の重み1）: メッシュ内の出力合計kW÷設備数。根拠: JPEA・REASP p.10（高圧は被害額最大と想定）。被害額の大きさの目安であり起きやすさの証拠ではない。
2. **低圧（50kW未満）の割合**（初期の重み1）: 根拠: JPEA・REASP p.10（警備の弱い低圧事業用も被害が増加）、茨城県警（小規模太陽光での発生が多い）。
3. **周囲の人の少なさ（参考）**（初期の重み0）: メッシュ人口÷(25×1.04km²)の人口密度が低いほど高い。根拠: JPEA・REASP p.9「人目につきにくい立地」、茨城県警「人や交通量の多くない場所」。常住人口で、夜間・見通し・道路は見ない。
指標の選択・重みに公的根拠はなく、的中率などの検証はしていない。重みが全て0なら、色分け・帯・凡例を止める（「色分けを停止中」を地図に表示）。

## 悪用を防ぐ設計（実装）
1. 個別設備の順位・一覧・点の表示なし。地図は約5kmメッシュ、表は市町村のみ。**メッシュの順位が作れない**: 画面（ポップアップ）・CSV・公開 JSON にメッシュの連続スコアや各指標の順位に当たる値はなく、5段階の帯（224メッシュが5つの帯に入る）だけ。並べ替えて作れるのは、元の認定情報から集計できる件数・出力計・人口などの並びで、これは本アプリが足した手がかりではない。
2. **秘匿のしきい値**（`build_data.py` の `K_MIN`・`DOM_N`・`KW_ROUND`）: (a) 設備3件未満のメッシュ・市町村は件数・容量・指標を出力しない（出力ファイルにも存在しない）。(b) 設備10件未満のメッシュは、50kW以上の設備が1件以下なら隠す。件数・出力計・50kW未満の件数から、その1件の出力が数十kWの幅で割り出せるため（アグレッサーの指摘で7メッシュ、隠す対象は条件に合う11メッシュ）。(c) メッシュの出力計は10kW単位に丸める。しきい値は最小限の目安で、統計的な匿名性の保証ではない。市町村合計とメッシュ合計の差から隠した分の合計は推定できる（画面の限界に明記）。
3. 自己診断: 位置（地図クリックまたは緯度経度）・設備区分・対策チェックリスト（茨城県警 Metal News 第4・10号、同「金属盗難に注意！」、同チラシ「太陽光発電所の窃盗対策」、JPEA・REASP p.9–10。項目ごとに出典）→ 周囲の目安（5段階）と未実施・不明の対策。計算はブラウザ内のみ。送信・保存なし（localStorage・Cookie・POST を使わないことを `tests/` で検査）。
   - **位置の粒度**: 診断が使う位置・人口は約5kmメッシュの単位だけ（同じメッシュ内の2点で結果が同じことを検査）。
   - **「送信しません」の正確な範囲**: 座標を入力しても地図は動かさない。地図は拡大を縮尺11（約16km四方のタイル。MapLibre の拡大率10）までに制限する。ただし地図を動かすと、見ている範囲の地図画像を地理院が受け取るので、**見ている範囲は地理院に伝わる**（画面に明記）。地図を見ずに座標入力だけでも診断できる。`tests/ui_check.mjs` が、座標入力・拡大操作の後に縮尺12以上のタイルを要求しないことを検査する。
   - **県内判定**: 入力の1kmメッシュが、茨城県の区域（e-Stat 小地域境界のポリゴン。水面を含む）に重なるメッシュ（`web/data/land.json`、ビルド時に生成）に入るかで判定し、海上・他県の座標は拒否する（鹿島灘・千葉・栃木・県外を検査）。
   - **座標の入力**: 全角を半角にし、符号付きの10進数だけを受け付ける。「36,34」「36.34abc」は拒否。
4. 盗難の実態は公的な粒度（全国・茨城県の年次、県内5地区）のみ。令和8年は暫定値、「9月末」が累計かは誌面に明記なしと画面に記載。
5. CSV は集計（メッシュ・市町村）のみ。目安は5段階の帯だけ。県警の実績との食い違いの注記を含む。
6. 元データの認定情報は地番まで公開されている。本アプリの秘匿は「他人に見つけられなくする」ものではなく、元データ以上の手がかり（手薄さの順位）を足さないためのもの。

## 画面

## 顧客と支払い（仮説。未検証）
誰が払うかの根拠はまだない（ヒアリングしていない）。次は仮説で、数値は書かない。
- **O&M事業者（有力な仮説）**: 契約先の発電所の定期点検に「盗難対策の確認票」として組み込み、O&M契約の費用に含めて発電事業者が負担する。使い方は、拠点の位置と区分を入れて、未実施・不明の対策を点検項目にすること。本アプリはブラウザ内で完結し、事業者の位置を預からない設計なので、O&M事業者が顧客のデータを外に出さずに使える点が価値。
- **発電事業者（自社設備の自己点検）**: 無償の公開ツールとして使う。単独では収益の接点がない。
- **保険会社**: 引受時の自己申告票としての利用が考えられるが、本案は設備単位の評価を出さない方針なので、価値が届きにくい（限界）。
- **自治体・警察の防犯担当**: 周知の材料（法第16条）。警察は被害地点の実データを内部に持つため、公開データの代理指標は不要で、集計と対策の一覧を周知に使う程度にとどまる。
- 事業性が弱いのは認める。提出するなら、アイデア部門（12/10）のほうが無理がない（部門は総司令官が決める）。

## 未解決・要確認
