# 太陽光発電所の盗難対策マップ（イチBizアワード2026・新案・最小デモ・茨城県）

新案NB（使用済みパネルの回収圏計画、`../business-nb/`）の構成を踏襲した別の案。入れ替えず並べて比べる。提出文は未作成（部門は総司令官が決める。ビジネス 11/30、アイデア 12/10）。

銅線ケーブル等の金属盗から太陽光発電所を守る対策の優先順位を、**公開データから作る「目安」**で考える静的Webアプリ。公開するのは約5kmメッシュと市町村の**集計だけ**で、個別設備の順位・一覧は出さない。事業者が自分の設備の位置と対策を入れる自己診断は、ブラウザ内だけで計算する。サーバー・APIキー不要。

## NB との違い（顧客・課題・成果指標）

| | NB 回収圏計画 | 本案 盗難対策マップ |
|---|---|---|
| 顧客候補 | 使用済みパネルの回収・リサイクル事業者、自治体 | 発電事業者、O&M事業者、保険会社、自治体・警察の防犯担当 |
| 解く課題 | 将来の大量廃棄に対する回収網の空白 | 銅線ケーブル等の金属盗への対策の優先順位づけ |
| 成果指標（案） | 回収圏外の設備の割合（直線距離・仮説） | 事業者が未実施の対策に気づけること、集計メッシュ・市町村の目安（被害の予測ではない） |
| 対象地域 | 京都府 | 茨城県（盗難が多い。情報部: 京都府は太陽光の被害が少ない） |
| 位置 | 地理院API（町字の代表点） | e-Stat 小地域の名称との突き合わせ（外部問い合わせなし） |
| 出し方 | 設備の点を地図に出す | 設備は出さず、集計（約5km・市町村）のみ。少ない集計は隠す |

成果指標は画面が出す値ではなく、提出文で検討する案。実効果の数値は何も主張していない。

## 実データか架空か
**実データ**。認定情報（茨城県ファイル、2026-10-31時点、取得 2026-11-13）の太陽光 **29,611件**のうち、運転開始報告済み **29,187件**（運転開始前424件を除く）を使用。出力は「発電出力（kW）」。
- 町字名を e-Stat 小地域（国勢調査2020）の名称と突き合わせて代表点を得た: 町字名が一致 **26,575件**、大字名で始まる小地域の代表点の平均 **2,075件**、対応づけられず市町村の集計のみ **537件（1.8%）**。
- 町字の面積は中央値 3.1km²、90%点 7.9km²で、1kmメッシュより粗い。このため公開の集計メッシュは1kmメッシュ×5＝約5km（東西約5.6km×南北約4.6km）にした。広い大字ではなお別のメッシュに数えられうる。
- 集計メッシュ: 設備のあるもの246、うち3件未満の11メッシュ（設備計18件）を隠し、**235メッシュ**を出力。
- 人口: e-Stat 地域メッシュ統計（国勢調査2020、基準地域メッシュ約1km、第1次区画 5339 5340 5439 5440 5539 5540）14,257メッシュ。「*」（近隣に合算済み）は0。
- 事業者名・代表者名・事業者住所・電話・設備IDは取り込まない。ビルド時に集計して捨て、公開物に個別設備の位置は残らない（`tests/test_app.py` が原データ全件の設備ID・名称・電話が公開物に無いことを検査）。

## 起動

```
cd contests/ichibiz-2026/app/solar-guard
python3 -m http.server 8835 --bind 127.0.0.1 --directory web   # http://127.0.0.1:8835/
```
`web/` をそのまま静的ホスティングできる。地図タイル（地理院）と MapLibre（unpkg、SRI付き）はブラウザが取得する。取得できなくても表・CSV・座標入力の診断は動く。

## データ生成
```
python3 fetch_raw.py     # 公開サイトから GET で raw/ に取得（認定情報・e-Stat 境界属性表・e-Stat メッシュ人口）
python3 build_data.py    # raw/ だけから web/data/ を生成（ネットワーク不要、再現可）
```
`raw/`（約31MB）は .gitignore。`web/data/checklist.json`・`reality.json` は出典付きの手書き（茨城県警・JPEA・REASPの資料を取得日 2026-11-13 に読んで転記）。

## 目安の指標の定義
3つの代理指標を、県内の集計メッシュ235個（市町村は44）の中での相対位置（0〜100、同値は平均順位）に直し、利用者が決める重み（0〜5、初期値は各1）で平均。色は五分位の5段階で、順位は出さない。
1. **周囲の人の少なさ**: メッシュ人口÷(25×1.04km²)の人口密度が低いほど高い。根拠: JPEA・REASP p.9「人目につきにくい立地」、茨城県警「人や交通量の多くない場所」。常住人口で、夜間・見通し・道路は見ない。
2. **設備容量のまとまり**: メッシュ内の出力合計kW。根拠: JPEA・REASP p.10（高圧は被害額最大と想定）。被害額の目安であり起きやすさの証拠ではない。
3. **低圧（50kW未満）の割合**: 根拠: JPEA・REASP p.10（警備の弱い低圧事業用も被害が増加）、茨城県警（小規模太陽光での発生が多い）。
指標の選択・重みに公的根拠はなく、的中率などの検証はしていない。画面に「被害の予測ではなく目安」と明記。

## 悪用を防ぐ設計（実装）
1. 個別設備の順位・一覧・点の表示なし。地図は約5kmメッシュ、表は市町村のみ。設備3件未満のメッシュ・市町村は件数・容量・指標を出力しない（`build_data.py` の `K_MIN`。出力ファイルにも存在しない）。しきい値3は最小限の目安で、統計的な匿名性の保証ではない。市町村合計とメッシュ合計の差から隠した分の合計は推定できる（画面の限界に明記）。
2. 自己診断: 位置（地図クリックまたは緯度経度）・設備区分・対策チェックリスト（茨城県警 Metal News 第4・10号、同「金属盗難に注意！」、同チラシ「太陽光発電所の窃盗対策」、JPEA・REASP p.9–10。項目ごとに出典）→ 周囲の目安と未実施・不明の対策。計算はブラウザ内のみ。送信・保存なし（localStorage・Cookie・POST を使わないことを `tests/` で検査）。位置は約5kmメッシュに直して使う。地図タイルは表示範囲を地理院から取得するため、その旨を画面に明記。
3. 盗難の実態は公的な粒度（全国・茨城県の年次、県内5地区）のみ。令和8年は暫定値、「9月末」が累計かは誌面に明記なしと画面に記載。
4. CSV は集計（メッシュ・市町村）のみ。

## 画面
最初に、使う人・できること・しないことと「被害の予測ではなく目安」を表示。タブ: 公開の集計地図／自分の設備を診断／盗難の実態（公的な粒度）／出典・前提・限界。

## 未解決・要確認
- 認定情報の利用ルールの禁止事項「国家・国民の安全に脅威を与える利用」に、この用途が当たらないかは判断していない（総司令官・事務局への確認が要る）。
- e-Stat の利用条件は取得ページで再確認していない（情報部の確認に依拠）。公開前に最新条件を確認。
- 法第16条（周知）の趣旨との整合は推測。令和7年法律第75号の条文は情報部の確認に依拠（本工兵は未読）。
- 目安は検証していない。被害の実績を設備単位・メッシュ単位で突き合わせる公開データはない。
- 5地区に含まれる市町村の範囲が誌面にないため、市町村表と地区別件数は対応づけていない。
- 20kW未満が元データにない。町字の代表点が大字内の実位置とずれる。
- 画面のスクリーンショットでは、地図タイルが取得できる環境でのみ地図が描かれる。
