# 住む場所の先行き（イチBizアワード2026 不動産情報活用部門・新案 RN1・動くデモ）

家や土地を買う前に、場所を地図で指す（または住所を検索する）と、市の立地適正化計画の区域・周りの将来人口（推計）・小学校区・徒歩圏の施設・災害の想定区域を、不動産情報ライブラリ（国土交通省）のデータから重ねた「先行きシート」を1枚出す。印刷（A4・1枚のPDF保存）できる。静的ファイルのみ。サーバー・APIキーは実行時に不要（取得は事前に済ませ、`web/data/` に同梱）。対象は徳島市のみ。

この案は**現行案（`../realestate/` の「相談前の1枚シート」）の追加の候補**で、入れ替えてはいない。提出文は `../../submission/realestate-rn1/`。報告（作業の記録）はこのファイル。

## 起動
```
cd contests/ichibiz-2026/app/realestate-rn1/web
python3 -m http.server 8827 --bind 127.0.0.1
# ブラウザで http://127.0.0.1:8827/ （地図画像を国土地理院から取るためネット接続が必要）
```
使い方: 「例の場所」（徳島駅付近・国府町・八万町）を選ぶか、地図をクリック（タップ）、または住所検索で移動してクリック。地図にフォーカスして矢印キー・＋/－・Enter でも操作できる。区域・災害の想定区域は、チェックボックスで地図に重ねられる。

### 取り直す手順（キーはファイル・ログ・出力に出さない）
```
cd contests/ichibiz-2026/app/realestate-rn1
node tools/fetch-reinfolib.mjs --check                                   # 取得する範囲と本数だけ表示（通信しない・キー不要）
node --env-file=<リポジトリ直下の環境変数ファイル> tools/fetch-reinfolib.mjs   # 取得して web/data/ を書く（約5分）
node --env-file=... tools/fetch-reinfolib.mjs --only XKT013,XKT026       # 項目を絞る（取れた項目だけ書き換え、他は残す）
node --test tests/lib_test.js tests/extract_test.mjs                     # 取り直した後の検査
```
- `--env-file` は環境変数にするだけで、スクリプトは環境変数ファイルを開かない。キーは `REINFOLIB_API_KEY` として Node のプロセス内だけに置かれ、リクエストヘッダにだけ使う。
- 失敗した項目は理由（HTTP番号など。応答本文・キーは含まない）を `manifest.json` に残し、画面は該当欄に「未取得（理由）」と出す。401/403 は他の項目も同じ原因なので即停止する。
- `--out <フォルダ>` で出力先を変えられる（試験用）。`tools/inspect-api.mjs` は応答の項目名だけを確認する補助（取得結果は保存しない）。
- 規約（API利用規約 第8条(2)）: ブラウザからは API を呼ばない。キーを画面・ファイルに出さない。同梱データにキーが入っていないことは tests/lib_test.js が検査（32桁以上の英数字がない、環境変数のキー値が含まれない）。

## 守っていること
- 出典・加工の旨・作成者の責任（国が作成・監修したものではない）・API利用規約のクレジットを、画面（フッター）と1枚シート（印刷にも入る）に表示。文言は `web/lib.js` の定数で、クレジットは規約のまま固定（テスト）。サービス名に「不動産情報ライブラリ」を含めない。
- 将来人口は推計である旨を、シートの節・フッター・提出文に明記。メッシュ単位でなく半径500mの合計で見る。
- 「住める・住めない」「価値が上がる・下がる」「買うべき」「安全・危険」の断定を出さない。区域の外でも住めること、区域の内外は住めるかや価格を示さないこと、市が公表する図が正であることを書く（徳島市内の格子点500地点の出力で、断定語が出ないことをテスト）。
- 数字は出典付きのみ。出典のある項目には、シートの各行の先頭に API の番号（XKT0xx）または「市の資料」「作成者の集計」の印を付ける。
- 取得できなかった項目は「未取得」と理由を出し、その行は出さない（「該当なし」と書かない）。
- 入力と指した位置は端末内のみ。保存・送信しない。外部へのリクエストは GET のみ（国土地理院のタイル・住所検索）。この画面から不動産情報ライブラリの API は呼ばない。
- 市の資料の引用: 徳島市「立地適正化計画 届出の手引」（令和7年4月）p.1〜3。居住促進区域（国の名称は居住誘導区域）の外で3戸以上の住宅を建てる開発・建築などは着手の30日前までの届出。1戸・2戸の住宅の建築は、手引の届出対象の例に入っていない。

## 限界
- 対象は徳島市のみ。立地適正化計画の区域は国の整備データ（令和7年度の都市計画決定GISデータ）で、市の最新の公表と異なる場合がある（市が公表する図が正）。市の公表図との照合は未実施。
- 将来人口は国土政策局の推計（令和2年国勢調査に基づく）。API の年齢別人口は2025年以降のみで、2025年も推計値。市の公式推計とは別物。メッシュは国の秘匿処理（小さい値の合算）を含む。
- 施設の位置は国土数値情報の整備年度（医療機関 令和2年度、学校・福祉施設・保育園等 令和5年度）。その後の閉鎖・開設は反映されない。徒歩圏は直線距離800m（規約の「1分=80m」は道路距離）。学校・病院が将来続くかは、データにない。
- 校区の子どもの数は、メッシュの中心が校区に入るものの合計（境界のメッシュは丸ごとどちらかに入る）。
- 区域・災害の判定は、指した1点が多角形・格子に入るかだけ。境界付近は誤差がある。立地適正化計画のデータは、タイルで切れた多角形の集まりで、タイルの境界の上の点は片方にだけ入る。
- 洪水浸水想定区域は河川の想定最大規模で、内水氾濫や小さな河川は含まれないことがある。浸水の深さは出していない（原典のコード定義を確認できていないため）。
- 土砂災害は警戒区域・特別警戒区域を区別していない。
- 法務・税務・購入判断の助言ではない。

## 未解決事項
1. 本人加筆（背景300字・課題110字・サービス200字）。家探し・移住・実家の周りの体験の有無と、地場の不動産会社または徳島市の都市計画課への聞き取り1件（personalize.md 手順0）。未記入のままでは提出できない（【本人加筆】が残る）。
2. 市の公表図との照合（居住誘導区域・都市機能誘導区域の境界）。国の整備データが市の最新の公表と一致するか。「データ上の区域設定日」（居住誘導区域 2024-04-01、都市機能誘導区域 2019-06-01）は API の値で、市の告示との照合は未実施。
3. 国内に同種の一般向けサービスがあるか（独創の点の前提）。情報部への調査依頼が必要（偵察レポート 第8節1）。
4. 同梱データの再配布の解釈（API利用規約 第1条(3)。憲兵の監査 N2 と同じ論点）。現行案の同梱は総司令官が承認済みだが、RN1 の同梱（約3.3MB）は未承認。
5. 洪水の浸水深・土砂災害の種別を出していない（原典のコード定義が未確認）。確認できれば追加できる。
6. デザイン審査班の審査・憲兵の監査・アグレッサーの試験は未実施。ダッシュボードへの組み込みも今回はしていない（指示どおり）。
7. 区域外の住民への配慮（自治体の意向と合うか）は、市の都市計画課への聞き取りで確認するのが望ましい。

9. API利用規約 第5条(5)により、3年間アクセスがないとキーが停止されうる（11/12 の改修報告による）。同梱データがあるので、画面の動作には影響しない。
