# イチBizアワード2026 採点基準（rubric）

- 元にした基準: contests/registry.json の criteria（独創性／社会的効果／実現可能性／事業性）。
- 追加した基準: 公式の例示（reports/intel/ichibiz-2026-20261109.md「審査」）にある「プレゼンテーション力」。一次は事務局の書類選考なので、「30秒で価値が伝わるか」として読む。
- 採点の手順: 基準ごとに、まず「審査員ならどこで減点するか」を書き、そのあとで点を付ける（交戦規定）。
- 3部門は同じ審査チームが続けて読む前提で採点する（3案の型が同じなら、プレゼンテーション力と独創性で減点する）。

## 足切り（点数より先に判定する。1つでも×なら「提出不可」）

| 項目 | ×の条件 | 根拠 |
|---|---|---|
| G1 生成AI条項 | 本文の中核（課題の具体例・着想・背景）がAI文のままで、本人が書く欄が飾り程度（目安: 各欄の3割未満。背景欄は本人が主） | 要項 p.7-8 |
| G2 虚偽・誇張 | 提出時点で事実でない記述（例: 動いていない物を「実証済み」）。根拠のない数値 | 要項・交戦規定 |
| G3 字数 | check_limits_divisions.py が exit 1 | 要項 p.4 |
| G4 交渉・知財・出典 | 協賛企業への交渉に見える記述。第三者の知財の無断利用。データの出典・ライセンス表記の誤り | 要項 p.7-8、ライブラリ約款 |

注: 【本人加筆】が残っている状態の採点では、G1 は「本人が書ける構成になっているか」で判定する。埋まっていないこと自体は総司令官の作業として扱う。

## 採点基準（各1〜5点）

### 1. 独創性
| 点 | 目安 |
|---|---|
| 5 | 既存サービス・公開地図との違いが冒頭で一文で言え、違いが検証できる。G空間技術の使い方にも工夫がある |
| 4 | 違いが本文の前半で明示され、具体名または一般名で既存手段と比べている |
| 3 | 新しい部分はあるが、本文の後半に埋もれている |
| 2 | 「重ねる・まとめる」が主で、既存手段との違いを書いていない／「と考えられる」で止まる |
| 1 | 既存サービスと同じ |
採点観点: 冒頭3文に新規性があるか。既存手段（名前は公式確認済みのものだけ）との差が書けているか。

### 2. 社会的効果（社会的インパクト）
| 点 | 目安 |
|---|---|
| 5 | 誰が・どれだけ困っているかが出典付きの公的事実で示され、具体的な1場面がある。効果の測り方も書いてある |
| 4 | 出典付きの事実か具体的な場面のどちらかが強く、対象が明確 |
| 3 | 対象は明確だが、根拠が推測（「と考えられる」）中心 |
| 2 | 総論だけで、困っている人の姿が見えない |
| 1 | 課題が不明 |
採点観点: 1文目に具体性があるか。根拠のない数値がないか（あれば G2）。

### 3. 実現可能性
| 点 | 目安 |
|---|---|
| 5 | データの入手先・利用条件・難所の扱いが具体的で、本人の実績（動く物・聞き取り）がある |
| 4 | データと難所の扱いが具体的。実績は予定として正直に書いてある |
| 3 | データ名はあるが、難所（データ欠損・権利・典型的な例外ケース）への答えが弱い |
| 2 | 中心のデータの入手先が不明、または典型ケースで機能が空振りする |
| 1 | 実現の道筋がない |
採点観点: 審査員の「それはどこから取るの？」「その場合はどうなるの？」に本文で答えられるか。

### 4. 事業性（持続性。特にビジネス部門）
| 点 | 目安 |
|---|---|
| 5 | 支払う人・価格の仮説・母数（出典付き）・最初の顧客の当てがある |
| 4 | 支払う人と価格の仮説（「仮説」と明示）と母数がある |
| 3 | 支払う人と収益の形はあるが、数字の手がかりがない |
| 2 | 誰が費用を持つかが書かれていない |
| 1 | 続ける仕組みがない |
採点観点: アイデア・不動産部門は「運営主体と費用の当て」を見る。ビジネス部門は収益モデルを見る。

### 5. プレゼンテーション力
| 点 | 目安 |
|---|---|
| 5 | タイトルと冒頭で30秒で価値が伝わる。専門用語が少ない。他の2案と語り口が違う |
| 4 | 価値は伝わるが、列挙が多い／一部に専門用語 |
| 3 | 読めば分かるが、冒頭が総論。他案と型が似ている |
| 2 | タイトルが長く専門的。3案が同じ型に見える |
| 1 | 何の提案か分からない |
