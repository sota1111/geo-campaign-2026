# 作品名

バス定時性カルテ

## 公開URL

（総司令官が静的ホスティングへ公開後に記入）

## 概要

バスの位置データ（GTFS-RT）を一定間隔で蓄積し、時刻表（GTFS）と突き合わせて、路線×時間帯の定時率、区間ごとに増える遅れ、団子運転（連続する2便が接近して走る状態）を地図と表で見える化するWebアプリです。位置データから停留所の通過時刻を推定し、時刻表との差を遅れとして集計します。画面には、集計に使った期間（何日分・いつ時点か）と、車両数・更新間隔・時刻表との一致率というデータの状況を常に表示します。サンプルが足りない路線は数値を出さず「サンプル不足」と示します。画面で見られるのは公開用の集計（路線・区間・時間帯）で、便ごとの推定などの詳細は事業者向けのCSVとして別に出力し、公開しません。事業者名を並べた順位付けはしません。事業者や自治体の担当者が、ダイヤの見直しや運用の改善を話し合う材料にするための道具です。サーバー不要の静的サイトで、スマートフォンからも見られます。

## 解決したい課題

バスの遅れは、乗継の失敗、折返し時間の不足、運転手の待機や配置の計画に影響します。一方で、事業者や自治体が「どの路線の・どの時間帯の・どの区間で」遅れが増えるのかを、継続的に確かめる手段は限られています。運行管理の専用システムは事業者の内部にあり、自治体や住民、近隣の事業者が同じ見方で状況を共有することは困難です。本作品は、公共交通オープンデータセンターで公開されているバスの位置データと時刻表だけを使い、追加の機器や費用なしで同じ見方を提供します。団子運転や特定区間の遅れが見つかれば、ダイヤの余裕時間の見直しや、停留所の位置・信号・乗降の集中といった原因の調査に進めます。【数値の記入欄: 実データでの測定結果（日数・事業者・路線・定時率など）は、昼間の蓄積後に記入する。現時点では実測値を書かない。】

## 使用データ

公共交通オープンデータセンター（CKAN）に登録された、CC BY 4.0 のバス関連リアルタイム情報（GTFS-RT）のうち、トークン不要の公開URLで配信されているもの24データセット（東京都交通局、仙台市交通局、とさでん交通、高知の各事業者、青森市、群馬県内の各事業者、京福バス、きよバスなど）を取得対象とし、実際に車両が確認できた事業者を集計します。時刻表は、同じセンターが配信する各事業者の静的GTFSを使います。チャレンジ限定ライセンスと基本ライセンスのデータは使いません。クレジット（事業者名・公共交通オープンデータ協議会・CC BY 4.0）と、位置からの遅れの推定・集計という加工を行った旨を画面に表示します。背景地図は国土地理院の地理院タイルです。取得はGETのみで、一定間隔で保存した記録から、停留所の通過時刻の推定、路線×時間帯・区間・団子運転の集計を前処理で行い、静的ファイルとして配信します。

## 特徴

1. 「いつ・どこで遅れるか」を、路線×時間帯（朝・日中・夕・夜）と、停留所間の区間で示します。区間で増えた遅れを色で表すので、遅れが生まれている場所が地図で分かります。
2. 団子運転を、時刻表で隣り合う同じ路線・方向の2便の通過間隔が、時刻表の間隔の4分の1未満になった割合で示します。間隔が大きく開く「間延び」も同時に数えます。
3. 数値の出し方に慎重です。サンプルが足りない行は数値を出さず、集計に使った期間、車両数、更新間隔、時刻表との一致率を常に見せます。定時の基準（1分早い〜5分遅い）などの設定は仮のものと明記し、画面と説明に出します。
4. 公開用の集計と事業者向けの詳細を分けます。画面は路線・区間・時間帯の集計だけで、便や車両を特定できる情報は公開しません。事業者は名称順に並べるだけで、順位は付けません。
5. 表示中の路線×時間帯表と区間表を、ボタン1つでCSV保存できます。事業者向けには、便ごとの推定を含む詳細CSVを別に出力します。
6. 推定ロジックは、合成データ（遅れの大きさを決めて作った走行）から遅れを取り戻せることを自動テストで確認しています。観測が途切れた区間や路線から離れた位置は、推定に使いません。

## 使い方

1. ページを開くと、取得済みの事業者が名称順に並びます。「事業者」を選びます。画面上部に、集計に使った期間（何日分・いつ時点か）が表示されます。
2. 「時間帯」を、全時間帯・朝・日中・夕・夜から選びます。
3. 「データの状況」で、車両数、位置の更新間隔、時刻表との一致率、遅れを推定できた便の数を確認します。品質の判定が「通過」でない事業者は、数値を参考として読んでください。
4. 「路線×時間帯の定時率・団子運転」の表で、路線ごとの定時率、5分を超える遅れの割合、遅れの中央値、団子運転の割合を見ます。「サンプル不足」の行は数値を出していません。
5. 地図の線の色は、停留所間で増える遅れです。線をタップすると、区間の名前と増える遅れが出ます。「遅れが増える区間」の表の行を選ぶと、地図がその区間へ移動します。
6. 各表の下のボタンでCSVを保存できます。下部の「出典・ライセンス・前提」で、データの出典、推定方法、定時や団子運転の基準、限界を確認できます。

## 今後の展開

次の段階として、位置データの蓄積期間を延ばし、曜日別（平日・土日）と季節の違いを見られるようにします。時刻表の道路形状（shapes）が提供されている事業者では、折れ線を道路に沿わせて推定の精度を上げます。TripUpdate（事業者の到着予測）の遅れ値が提供されている場合は、位置からの推定との突き合わせで検証します。事業者や自治体の担当者へのヒアリングを行い、定時の基準、団子運転の定義、事業者向けCSVの項目を実務に合わせて見直します。また、祝日・臨時ダイヤ・運休の反映と、現行の生活アクセス診断マップ（行ける・行けないの診断）との連携により、遅れが住民の行き先への到達にどう影響するかも見られるようにします。収録する事業者は、データとライセンスの確認ができたところから順次追加します。
