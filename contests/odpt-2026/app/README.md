# 生活アクセス診断マップ

地区ごとに、平日・休日の朝・昼・夕に「公共交通で病院・小中学校へ行けるか」を地図で診断する静的Webアプリ。
サーバー不要。`web/` をそのまま静的ホスティングに置けば動く。

- 提出先: 公共交通オープンデータチャレンジ2026（odpt-2026）／アーバンデータチャレンジ2026（udc-2026・アプリケーション部門・テーマ「道路・交通」）。同一アプリを両方に出す。
- 診断の問い: 「その時間に家（500mメッシュの中心）を出て、徒歩→公共交通（乗継可）→徒歩で、W分以内（20/30/45/60分）に施設の近くへ着けるか」。待ち時間・乗継時間を含む。
- 機能: 地図の塗り分け（歩いて行ける／公共交通で行ける／行けない／鉄道駅が近い（未評価））、人口・65歳以上人口での集計、平日/休日×朝昼夕の比較表、地点クリックで近くの停留所の本数・終発・路線、停留所の本数による色分け、路線を止めた場合の差分（「路線を止めたら？」。事業者・路線名でまとめた単位）、収録範囲とデータ期限の常時表示、出典・ライセンス・前提の表示、スマホ表示（結論を最初の画面に固定表示）。色は赤と緑の対比を避けた配色。

## 起動（確認用）

```
cd contests/odpt-2026/app/web
python3 -m http.server 8000      # http://localhost:8000/ を開く（file:// では fetch が使えない）
```

生成済みの `web/data/` が入っているので、ビルドなしで動く。地図タイルとMapLibreはインターネットから読み込む。

## ビルド（データの再生成）

Python 3.10以上、標準ライブラリのみ（pip不要）。インターネット接続が必要（GTFSデータリポジトリ・国土数値情報・e-Stat）。

```
cd contests/odpt-2026/app
python3 build.py                        # 取得（cache/に保存・再利用）→ web/data/*.json を生成
python3 build.py --today 2026-11-09     # 診断の基準日の起点を固定（再現用）
python3 build.py --region toyama        # 1地域だけ
python3 build.py --whatif-top 0         # 「路線を止めたら？」の事前計算を省く
```

- 診断の基準日: 各フィードの有効期間内で、`--today` 以降の最初の水曜（平日）と日曜（休日）。祝日ダイヤ・臨時ダイヤは反映しない。
- データの期限: 各フィードに `expired`（作成日時点で期間切れ）と `ends_before_public_end`（公開期間の終わり2027-03-12より前に切れる）を付けて出力し、画面の「データの期限」欄・出典表で警告する。画面は、開いた日の日付とも照らして期限切れを警告する。
- 所要時間: 地域ごとに数分〜十数分（路線除外の再計算が大半。東京は都営バスの路線数が多く最も長い）。地域は `--region` で別々に並列ビルドでき、そのあと `python3 build.py --reindex` で `index.json` を作り直す。
- ODPTセンターのGTFS（`regions.json` でオブジェクト形式で記載した feeds）は、キーなしの公開APIから取得する（`lifemap/odpt_adapter.py`）。有効期間は都営バスが2029-11-08まで、都営地下鉄等が2027-03-12まで。
- 公開前に最新のGTFSで作り直すこと（データ有効期間が切れると基準日がずれる）。

## デプロイ（GitHub Pages等・総司令官が実施）

`web/` ディレクトリの中身だけを静的ホスティングに置く。パスはすべて相対なので、サブディレクトリ配下（`https://<user>.github.io/<repo>/`）でも動く。ビルド工程・サーバー・APIキーは不要。

GitHub Pages の例: リポジトリ設定でPagesの公開元を `web/` を含むブランチ／フォルダにする（`/docs` 以外を使う場合は GitHub Actions で `web/` を成果物にする）。公開は応募期間〜開催期間（ODPTは2027/3/12まで）無償・誰でも利用できる状態にすること。

## 診断の前提と限界（画面にも表示）

- 徒歩は直線距離×1.25を分速80mで歩く概算（道路網・坂・横断は未考慮）。乗車停留所は直線600m以内、降車停留所から施設は直線500m以内、乗継は3分以上。徒歩だけで行けるかも**同じ徒歩モデルと許容時間**で判定する（許容時間W分以内に歩いて着けるなら「歩いて行ける」。W=20分なら直線1280m、60分なら3840m）。「行けない（赤）」は、歩いても公共交通でもW分以内に着けない場合だけ。
- 停留所は、40m以内、または同名で150m以内のものを1つの停留所群に統合（事業者間の乗継を可能にするため）。
- 診断範囲は、収録停留所から2km以内の人口メッシュ。未収録事業者のみが走る地区は「空白」に見えることがある。
- 収録しているのはバス等のGTFSだけで、JR等の鉄道・デマンド交通は未収録（東京は都営地下鉄等を収録）。この旨を主要画面に常時表示し、国土数値情報N02の駅（`regions.json` の `rail_covered` に書いた収録済みの事業者・路線は除く）から徒歩15分圏（直線960m）で行けない地区は、赤ではなく灰色「鉄道駅が近い（未評価）」にする。N02は令和4年12月31日時点で、新設・廃止は反映されない。
- 評価していないもの: 運賃、デマンド交通の予約、バリアフリー、施設の診療・受付時間、帰りの便、遅延・運休。
- 65歳以上人口は国勢調査の秘匿処理で近隣メッシュに合算されている場合がある。
- 「買い物」は未対応（キー不要で取得できる全国一様の商業施設データを確認できていない）。行き先は病院・小中学校。
- 「路線を止めたら？」は、（事業者, route_short_name, route_long_name）でまとめた路線ごとに、方向・系統の違うGTFSのrouteも含めて全便を除いて再計算した結果。名称が違えば別の路線として扱う（上りと下りで名称が違うフィードでは別々に選ぶ）。部分的な減便や代替バスは考慮しない。

## 画面の操作（初見ユーザー試験を受けた改善。2026-11-11）

- 見出し直下のショートカット（地点を調べる／路線を止めたら？／地域を比べる／出典・前提）、5地域のボタン（いまの地域を「✓」と見出しで表示）。地図は開始地域の center で初期化する。
- 地点の診断: 地図をクリックすると、現在の条件で「この地点から平日朝8時に出発すると、病院へ30分以内に 行けます（歩いて／公共交通で）／行けません」を詳細の先頭に大きく表示し、もう一方の曜日（休日は日曜ダイヤ）との比較を一言添える。地図上にも同じ結論のポップアップを出し、詳細へスクロールする。同名の停留所は路線名で区別して表示する。
- 住所・駅名検索: 国土地理院の地名検索API（`GET https://msearch.gsi.go.jp/address-search/AddressSearch?q=…`、キー不要）。入力値はクエリにだけ使い、結果の位置が5地域のどの bbox に入るかで地域を自動切替し、範囲外ならその旨を表示する。検索したときだけ入力文字列が国土地理院へ送られる（GETのみ）。出典（国土地理院）は「出典・ライセンス・診断の前提」にも記載。
- 共有リンク: `#region=…&f=行き先&d=曜日&p=時間帯&w=許容時間&r=選択路線&pt=経度,緯度` を常に更新し、読み込み時に復元する。「この画面のリンクをコピー」ボタンあり。旧形式 `#region=xxx` も読める。
- 出典の例文: 地域の収録事業者・ライセンスを含む文面と、コピーボタン（共有欄と出典モーダル）。
- 集計に「行けない人: 全体／65歳以上（人数と%）」、「路線を止めたら？」に前提（全便停止・代替交通と減便は考慮しない）と選択中の路線の表示・解除ボタン。
- 地域比較: 「同じ条件で5地域を比べる」を押したときだけ全地域のJSONを読み、行ける割合・行けない人数（全体・65歳以上）を表にする。収録範囲が違う注意書き付き。
- 画面の確認: `cd web && python3 -m http.server 8812 --bind 127.0.0.1` を起動し `node tests/aggressor_ui.mjs http://127.0.0.1:8812/ <出力先>`（Chrome要）。共有リンク・検索（fetchを差し替えて模擬）・比較の場面を含む。

## 拡張点

- ODPTセンターのデータ追加: `regions.json` の feeds にオブジェクト（`source: "odpt"`, `path`, ライセンス・クレジット）を足すだけ。形式は `lifemap/odpt_adapter.py` の docstring。キーが要るAPI（JSON形式のリアルタイム情報等）は使っていない。
- 施設の種類: `lifemap/sources.py` に読み込み関数を追加し、`lifemap/build.py` の `fac`・`FACILITY_LABELS` に登録（診断文字列は 施設数×6桁で自動的に増える）。
- 地域の追加: `regions.json` に追加して `python3 build.py`。
