# 生活アクセス診断マップ（仮称）

地区ごとに、平日・休日の朝・昼・夕に「公共交通で病院・小中学校へ行けるか」を地図で診断する静的Webアプリ。
サーバー不要。`web/` をそのまま静的ホスティングに置けば動く。

- 提出先: 公共交通オープンデータチャレンジ2026（odpt-2026）／アーバンデータチャレンジ2026（udc-2026・アプリケーション部門・テーマ「道路・交通」）。同一アプリを両方に出す。
- 診断の問い: 「その時間に家（500mメッシュの中心）を出て、徒歩→公共交通（乗継可）→徒歩で、W分以内（20/30/45/60分）に施設の近くへ着けるか」。待ち時間・乗継時間を含む。
- 機能: 地図の塗り分け（徒歩圏／公共交通で到達／到達できない）、人口・65歳以上人口での集計、平日/休日×朝昼夕の比較表、地点クリックで近くの停留所の本数・終発・路線、停留所の本数による色分け、路線を止めた場合の差分（「路線を止めたら？」）、出典・ライセンス・前提の表示、スマホ表示。

## 対象地域（4地域）と選定理由

「全国」ではない。GTFSデータリポジトリで地方・自治体系バスのデータが揃い、人口メッシュと施設データが取れる地域に絞った。

| id | 地域 | 収録（事業者数） | 選定理由 |

| toyama | 富山市周辺 | 富山地方鉄道(バス・市内電車)、富山市コミュニティバス7系統、上市町、立山町 | 幹線と地域バスの接続を診断できる。全データ CC0 |
| tokushima | 徳島市周辺 | 徳島市営バス、徳島バス、上八万、松茂町、北島町、鳴門市地域バス | 中小都市圏で自治体バスが通院・通学を支えているかを診断できる |
| iida | 飯田市・下伊那 | 南信州広域連合の飯田市・松川町・高森町・喬木村・豊丘村・信南交通など8データ | 人口が少なく路線が疎な中山間地域との対比を示せる |

地域・収録フィードの定義は `regions.json`。JR・大手民鉄など、GTFSデータリポジトリに未収録の事業者は含まれない。画面の「出典・ライセンス・診断の前提」に収録事業者・ライセンス・更新日・診断の基準日を表示する。

## 起動（確認用）

```
cd contests/odpt-2026/app/web
python3 -m http.server 8000      # http://localhost:8000/ を開く（file:// では fetch が使えない）
```

生成済みの `web/data/` が入っているので、ビルドなしで動く。地図タイルとMapLibreはインターネットから読み込む。

## ビルド（データの再生成）

Python 3.10以上、標準ライブラリのみ（pip不要）。インターネット接続が必要（GTFSデータリポジトリ・国土数値情報・e-Stat）。

```
cd contests/odpt-2026/app
python3 build.py                        # 取得（cache/に保存・再利用）→ web/data/*.json を生成
python3 build.py --today 2026-11-09     # 診断の基準日の起点を固定（再現用）
python3 build.py --region toyama        # 1地域だけ
python3 build.py --whatif-top 0         # 「路線を止めたら？」の事前計算を省く
```

- 診断の基準日: 各フィードの有効期間内で、`--today` 以降の最初の水曜（平日）と日曜（休日）。祝日ダイヤ・臨時ダイヤは反映しない。
- 所要時間: 全4地域で数分（路線除外の再計算が大半）。
- 公開前に最新のGTFSで作り直すこと（データ有効期間が切れると基準日がずれる）。

## テスト

```
cd contests/odpt-2026/app
python3 -m unittest            # 全テスト
python3 -m unittest discover -s tests -v
```

- 前処理: 時刻・カレンダー（例外日含む）・基準日・時刻補間・bbox 絞り込み・停留所統合・本数集計・人口メッシュ(cp932)の読み込みと500m集約・施設の抽出。
- 診断ロジック: 後退走査が、独立に書いた前方探索と一致すること（乱数の合成ネットワーク、および実データ=富山の60メッシュ×3時間帯。キャッシュがある場合のみ）。乗継時間・同一便通過・期限の扱い。
- 通し試験: 合成データで `build_region` を実行し、出力構造・ライセンス保持・診断結果を確認。
- 生成データ: 容量(各3MB未満)・全フィードにライセンス表示・参照整合性・地域数3〜5。
- フロントの純粋関数（`web/lib.js`）: Node.js がある場合のみ実行。
- 画面の目視確認（任意）: `node tests/ui_shot.mjs <url> <out.png> <幅> <高さ>`（Chromeが必要）。

## デプロイ（GitHub Pages等・総司令官が実施）

`web/` ディレクトリの中身だけを静的ホスティングに置く。パスはすべて相対なので、サブディレクトリ配下（`https://<user>.github.io/<repo>/`）でも動く。ビルド工程・サーバー・APIキーは不要。

GitHub Pages の例: リポジトリ設定でPagesの公開元を `web/` を含むブランチ／フォルダにする（`/docs` 以外を使う場合は GitHub Actions で `web/` を成果物にする）。公開は応募期間〜開催期間（ODPTは2027/3/12まで）無償・誰でも利用できる状態にすること。

## 診断の前提と限界（画面にも表示）

- 徒歩は直線距離×1.25を分速80mで歩く概算（道路網・坂・横断は未考慮）。乗車停留所は直線600m以内、降車停留所から施設は直線500m以内、乗継は3分以上。施設まで直線800m以内は「徒歩圏」。
- 停留所は、40m以内、または同名で150m以内のものを1つの停留所群に統合（事業者間の乗継を可能にするため）。
- 診断範囲は、収録停留所から2km以内の人口メッシュ。未収録事業者のみが走る地区は「空白」に見えることがある。
- 評価していないもの: 運賃、デマンド交通の予約、バリアフリー、施設の診療・受付時間、帰りの便、遅延・運休。
- 65歳以上人口は国勢調査の秘匿処理で近隣メッシュに合算されている場合がある。
- 「買い物」は未対応（キー不要で取得できる全国一様の商業施設データを確認できていない）。行き先は病院・小中学校。
- 「路線を止めたら？」は、路線（GTFSのroute）ごとに全便を除いて再計算した結果。部分的な減便や代替バスは考慮しない。

## 拡張点

- ODPTセンターのデータ: `lifemap/odpt_adapter.py` の docstring に、追加時に返すべきデータ形式を記載。キーは環境変数から読み、リポジトリに含めない。
- 施設の種類: `lifemap/sources.py` に読み込み関数を追加し、`lifemap/build.py` の `fac`・`FACILITY_LABELS` に登録（診断文字列は 施設数×6桁で自動的に増える）。
- 地域の追加: `regions.json` に追加して `python3 build.py`。
