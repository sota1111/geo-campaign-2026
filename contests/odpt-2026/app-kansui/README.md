# 大雨のときに避けたい駅の出入口と迂回（比較用の案）

公共交通オープンデータチャレンジ2026（odpt-2026）向けの、**比較用の別案**です。現行の案（`../app/` 生活アクセス診断マップ、`../app-teiji/` バス定時性カルテ）とは独立しており、どちらも変更していません。

## 目的

大雨のとき、地下駅や低い場所にある駅は、出入口や周りの道が冠水しやすいと言われます。この案は、**浸水想定（洪水・高潮のハザード）と駅の出入口の位置を重ね**、

- 駅を選ぶと、出入口ごとの**想定浸水深の区分**と「避けたい／注意／着色なし」を示す
- 避けたい出入口の**代わり**として、同じ駅の別の出入口・隣の駅・近くのバス停（その停留所の平日・休日の便数、始発・終発、時間帯別の便数）を示す
- 地区全体で「**浸水想定のある出入口が多い駅**」の一覧を出し、**CSV**（駅ごと／出入口ごと）で書き出せる

ものです。利用者は、駅を使う住民・通勤者、施設管理者・自治体です。

**これは想定（ハザード）であり、実際の冠水の予測ではありません。** 「この出入口は安全」とは示しません。「着色なし」は、この想定図に色がないという意味です。

## 対象地域

東京都区部の中央部〜東部（南 35.63・西 139.70・北 35.74・東 139.88 の範囲。千代田・中央・港・新宿・渋谷の東部・文京・台東・墨田・江東・江戸川の西部など）。213駅・1,334出入口（OSM に記録のあるもの）・バス停 1,195（候補に出すのは、便のあるもののみ）。

選んだ理由（2026-11-15 に curl／urllib の GET で確認）:

- 必須データの都営バス GTFS-JP が**トークン不要で取得できた**（`https://api-public.odpt.org/api/v4/files/Toei/data/ToeiBus-GTFS.zip`、ODPT・CC BY 4.0）。
- 国土地理院「重ねるハザードマップ」の洪水（想定最大規模）と高潮（想定最大規模）のタイルが、この範囲で取得できた。
- 地下鉄の出入口が OSM に多数記録されている。東部の低地（江東デルタ）と、山手の高台（六本木・代々木など）が同じ範囲にあり、区分に差が出る。

## 判定の方法と限界

1. 各地点（出入口・駅・バス停）の経緯度を、国土地理院タイル（ズーム17、1画素約1m）の画素に変換し、**周囲3×3画素（約±1m）の最大値**の色を読みます。色→区分は、重ねるハザードマップの凡例画像の色から対応づけています（`kansui/hazard.py`）。
2. 区分は 0〜6（着色なし／0.5m未満／0.5〜3m／3〜5m／5〜10m／10〜20m／20m以上）。洪水と高潮のうち**大きい方**を出入口の区分とします。
3. **避けたい** = 区分2以上（想定浸水深 0.5m 以上）、**注意** = 区分1（0.5m 未満）、**着色なし** = 0。0.5m という線引きは、凡例の区分の切れ目に合わせた**この案での目安**で、行動の基準を示すものではありません。
4. **代わりの候補**は、区分が「より低い」ものだけを出します。同じ駅の別の出入口、直線 1.5km 以内の隣の駅（その駅で区分が最も低い出入口）、500m 以内で便のあるバス停（その地点の区分も併記）。距離は**直線**で、道のりや、冠水した道を避けた迂回路ではありません。
5. 駅への出入口の割り当て: 名前に駅名を含む出入口は 600m 以内、そうでなければ最寄りの駅の 300m 以内。同名の駅ノードは 400m 以内なら1駅にまとめます。割り当てられない出入口は 15 件ありました（画面下部に件数を表示）。
6. 便数は、フィード開始日以降の最初の水曜（平日、2026-11-18）と日曜（休日、2026-11-15）の運行分。終点での「発車」は数えません。24時超の時刻は 23時台に入れます。

限界（画面にも書いています）:

- **内水（雨水出水）の想定は含みません。** 重ねるハザードマップの内水タイルに、この地域の図が無かった（`02_naisui_data` は該当タイルなし）ためです。都市の局地的な大雨で起きる冠水は、洪水・高潮の想定だけでは表せません。指示にあった「洪水・内水・高潮」のうち、洪水と高潮だけです。
- タイルは地面の高さの想定です。地下駅の出入口の階段やシャッター、止水板、周囲の盛土・段差は反映していません。「着色なし」でも、安全とは言えません。
- 東京都の図面は 0.1m 未満を着色しないため、浅い浸水は見えません（国土地理院の備考）。
- OSM の出入口は、全てが記録されている保証がなく、位置もずれることがあります。地下鉄・JR・私鉄の便や、都営バス以外のバスは含みません。
- 雨量の実況・予報は組み込んでいません。大雨のときは、気象庁の防災情報（https://www.jma.go.jp/bosai/）、鉄道会社・自治体の案内と現地の状況を優先してください。
- このアプリの効果（冠水の回避が実際にどれだけ進むか）は検証していません。

## 起動方法

静的サイトです（サーバー側の処理・APIキーは不要）。

```
cd contests/odpt-2026/app-kansui/web
python3 -m http.server 8000      # http://localhost:8000/ を開く
```

`web/data/kansui.json`（約 0.8MB）は作成済みで含まれています。地図（MapLibre GL JS と地理院タイル）の表示にはインターネット接続が必要です。画面からの送信はありません（取得のみ）。

### データの作り直し（任意）

```
cd contests/odpt-2026/app-kansui
python3 -m kansui.build        # Python 3.9+、Pillow が必要。取得は GET のみ
```

OSM（Overpass）、都営バスの GTFS（約 7MB）、国土地理院のタイル（約 3,000 枚）を `cache/` に保存してから `web/data/kansui.json` を作ります（初回は数分〜10分ほど）。範囲は `kansui/build.py` の `REGION` で変えられます。`cache/` はコミットしません。

### テスト

```
cd contests/odpt-2026/app-kansui
python3 -m unittest discover -s tests     # Python（Pillow があるとタイルの色の読み取りも検査）
node tests/lib_test.js                    # 画面側の関数（CSV・並び順・文言）。上の unittest からも呼ばれる
```

## 構成

- `kansui/` データ作成: `osm.py`（駅・出入口）、`gtfs.py`（バス停の便数）、`hazard.py`（タイルの色→区分）、`analysis.py`（突き合わせ・代わりの候補）、`build.py`
- `web/` 静的サイト: `index.html`、`app.js`（画面・地図）、`lib.js`（CSV など、Node でも動く）、`style.css`、`data/kansui.json`
- `tests/` Python unittest と Node のテスト

## 画面の方針

- 色は青・橙。「避けたい（▲）／注意（△）／着色なし（○）」は色に加えて記号と文言でも示す。
- スマホ幅（390px で確認）でも横スクロールなし。外部への送信なし。
- 最初に地区全体の件数と「出入口が多い駅」の一覧を出し、駅の行を押すとその場で詳細が開く。
