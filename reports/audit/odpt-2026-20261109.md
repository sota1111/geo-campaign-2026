### 要修正

**A. 再ビルド後に description の数値を突合し直す（データの期限と数値の一致）**
- 事実: 現在の web/data は 2026-11-09 に生成。アグレッサー計測（reports/aggressor/odpt-2026-20261109.md §0）では、熊本の4フィードが 2027-02-10〜12、飯田（喬木村）が 2027-01-29 に切れる。締切（2027/1/11）には間に合うが、ヒアリング（1/23〜24）の直後、表彰式（2/20）・公開義務期間（〜3/12）の途中で切れる。ただし、その後のデータ再生成（commit 38d3cd7）で変わっていないか、私は確認していない。README は「公開前に最新のGTFSで作り直すこと」と書いている。画面は、期限切れと「公開期間の途中で終了」の警告を出す（app.js renderCoverage、出典表）。
- 根拠: intel §1 S4（締切後も、登録内容から大きく逸脱しない保守・バグ修正は可。ただし審査の公平性に影響すると判断されれば対象外）、§5（公開期間 〜2027/3/12）。
- 問題: description.md の数値（東京95.3%、熊本73.3%、徳島70.1%、富山60.5%、飯田39.4%、飯田の歩行39.2%・公共交通0.2%、東京の26.3%）は、特定のビルド結果の値。再ビルドすると変わりうる。説明文は提出後に編集できない。
- 突合の状況: 私は web/data の本体を開けず、これらの数値を突合できていない（実施できなかったこと）。整合性の確認として、次の点は確認できた。(1) 飯田の 39.2 + 0.2 = 39.4。(2) 30データ = 5+11+6+8。(3) 5地域。アグレッサーが再現したのは修正前の数値（飯田 休日25.2%・平日39.1%、熊本83.5%）で、現行の description の値とは別。
- 求める対応（作戦研究班または工兵）: 提出直前に最新のGTFSで再ビルドする（`--today` は祝日・年末年始を避ける。アグレッサー D5 の `test_weekday_ref_avoids_exception_day` は現在 expectedFailure のまま。README §テスト）。その後に description の全数値を web/data と突合して書き直す。突合の結果を reports/ops/ に残す。
- 締切後にデータを更新する場合は、「保守」に当たるかを主催者に確認する（要確認）。

**B. データ利用規約の未確認（ODPTセンター、e-Stat、国土数値情報）**
- 事実: README は「ODPTセンター・e-Stat・国土数値情報の規約全文は取得・確認していない」と書いている。ODPTのCC BY 4.0 は CKAN のカタログ記載から（2026-11-09確認）。ODPT開発者サイトの規約ページは、情報部も取得できていない（intel §要確認3、取得失敗リスト）。ODPT のGTFSの「キー不要」は、README・odpt_adapter.py が実機確認を主張しているが、情報部の調査は未確認としている（intel §7）。
- 影響: description に「公開API（キー不要）」「CC BY 4.0」と断言している。ライセンス・クレジット・再配布（web/data に派生データを静的JSONとして含める）の条件が違う場合、説明文が事実と違うことになり、提出後に直せない。
- 求める対応: 総司令官が開発者サイトにログインして規約を確認する、または主催者に問い合わせる（G3）。結果が「問題なし」なら、README の「全文は未確認」の記述を更新する。クレジットの書式に指定があれば画面に反映する（アグレッサー D10: e-Stat は推奨のクレジット書式に合わせる）。

**C. フォームの字数・項目の未確認**

- 求める対応: 総司令官がフォームを見て、項目名・字数・動画やソース公開の要否を情報部に伝える。情報部が registry.json（承認後）に上限を登録し、憲兵が再監査する。
