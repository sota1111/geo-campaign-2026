# アグレッサー報告: odpt-2026／UDC2026① 「生活アクセス診断マップ（仮称）」（2026-11-09）

## 結論
- **失格級（の可能性）1件と、手続き上の未確認が1件ある。** 応募資格の「公共交通オープンデータセンター**および**GTFSデータリポジトリで公開されているデータの活用」に対し、ODPTセンターのデータを使っていない。説明文にも「使用していません」と書いてある。「どちらか一方でよい」と読める可能性は高いが、公式の文言からは確定できない（intel §要確認4）。→ reports/escalations/20261109-odpt-center-data.md にも記録した。
- **落選級は3件。** (R1) 「到達できない（赤）」の人口の大半は、アプリ自身の徒歩モデルなら許容時間内に歩いて着ける（例: 富山・病院・60分では赤の96%）。(R2) 未収録の鉄道（JR・あいの風とやま鉄道・地鉄の鉄道線・JR飯田線）とデマンド交通の地区が赤で塗られる。背景地図に線路が見えているのに赤なので、審査員にすぐ見抜かれる。(R3) 「路線を止めたら？」は路線が GTFS の route_id 単位（方向別・系統別）に分かれている。富山では同じ名前の路線が51組あり、利用者には区別できない。影響も小さく出る。
- 技術の土台は堅い。後退走査は独立の実装と照合済み。生成データ、メッシュとクリック位置の対応（26,646点）、24時超の時刻、座標欠損、施設ゼロ、大きいフィード（約11万接続を1.2秒）はどれも問題なかった。弱点は計算そのものより、**診断の定義と見せ方**にある。

## 1. 弱点（重大度順）

### E1【失格級（可能性）】ODPTセンターのデータを使っていない（応募資格）
- 要項（S1）の必須条件は「公共交通オープンデータセンターおよびGTFSデータリポジトリで公開されている公共交通オープンデータの活用」。本作品はGTFSデータリポジトリだけを使う。description.md は「公共交通オープンデータセンターのAPIは今回は使用していません」と明記している。
- 「および」は公開場所を並べただけで、どちらか一方のデータで足りる、と読むのが自然（推測）。ただし両方必須かどうかは公式の記載から確定できない（intel §要確認4）。説明文は提出後に編集できない（S4）。
- 審査員の視点: 主催者はODPTセンターの運営側。「センターのデータを使っていない」と自分で書いた作品は、資格を満たしていても「オープンデータ活用によるインパクト」で不利になる。
- 対策（作戦研究班・総司令官）:
  1. FAQ・問い合わせ窓口で「GTFSデータリポジトリのみの活用で応募資格を満たすか」を確認する。送信は総司令官。
  2. 安全策として、ODPTセンターのデータを最低1種類組み込む。例: 対象4地域でODPTセンターが配信しているバス・鉄道データ、または全国の鉄道駅データで「未収録の鉄道駅」を地図に示す（R2の対策を兼ねる）。ただし ODPTセンターのデータには「チャレンジ限定ライセンス」のものがあり、利用期間や再配布の条件が違う可能性がある。規約は情報部が確認すること。センターのデータを使う場合は、センター所定の免責文言を画面に表示する必要があるかも確認する。
  3. 少なくとも description.md の「使用していません」は消す。「今後追加する」の書き方にとどめる。

### E2【失格級（手続き・未確認）】公開URLが未記入、開発者登録とエントリーの状況が不明
- description.md の公開URLは空欄。要項は「開催期間中、誰でも無償で利用できる状態で公開」を求めている（S1, S2）。開発者登録の確認には最大2営業日かかる（S2）。
- アプリの弱点ではないが、失格に直結する。憲兵の監査項目に入れること。

### R1【落選級】「到達できない」の大半は、アプリ自身の徒歩モデルなら歩いて着ける（社会課題・技術・UI）
- 画面の問いは「W分以内に病院へ行ける人は X%」。徒歩だけで行けるかの判定は「直線800m以内」に固定されている（access.WALK_ONLY_M）。許容時間を60分にしても、900mの病院（アプリの計算で約14分）は「到達できない（赤）」になる。
- 計測（§0）: 富山の病院・60分では赤の96%、熊本の学校・60分では赤の97%がこれに当たる。description.md の「飯田の休日 25.2%」も、赤の78%は歩けば60分以内になる。
- 審査員の視点: 地図では、青（徒歩圏）のすぐ隣のメッシュが赤になっている（A_desktop.png, D_whatif.png）。「病院の隣の地区が行けないのはなぜか」と最初に聞かれる。定義が一貫していないと、技術的な完成度が疑われる。
- 対策: 定義を一つに決める。(a) 歩くだけの所要時間も許容時間で判定する（徒歩上限を例えば20分と明示する）。(b) 赤の意味を「公共交通では着けない（施設は徒歩800m圏外）」に改め、凡例と見出しを変える。(b) なら見出しの「行ける人は」も「公共交通または徒歩800m以内で行ける人は」に直す。
- 失敗テスト: `test_walk_1km_counts_as_reachable_within_20min`、`test_red_cells_are_not_walkable`

### R2【落選級】未収録の鉄道・デマンド交通の地区を「到達できない」と塗る（データなし＝行けない）
- 富山の画面（D_whatif.png）では、背景地図に描かれたあいの風とやま鉄道・地鉄本線・上市方面の線路の上が赤い。熊本のJR鹿児島本線・豊肥本線、徳島のJR各線、飯田のJR飯田線も同じ。
- 「未収録」の説明は「出典・ライセンス・診断の前提」のモーダルの中だけにある。メイン画面には書いていない（`mentions_unlisted_on_main=false`）。地図の凡例にも、メッシュの色の意味が無い（凡例は停留所の色だけ）。
- description.md の課題文は「コミュニティバスやデマンド型の便」に触れている。しかしデマンド交通は診断の対象外。課題と手法が合っていない（UDCの「実用度」）。
- 審査員の視点: 交通事業者や自治体職員の審査員は、「駅前が赤」を見た時点で診断全体を信じなくなる。ODPTの特別賞にはJR東日本賞がある。鉄道を無視した診断は通りにくい。
- 対策: 鉄道駅（国土数値情報 N02 駅データ、またはODPTセンターの鉄道データ）の周辺を「対象外（灰色）」にする。またはメイン画面の見出しの直下に「JR等の鉄道・デマンド交通は含みません」と常に表示する。

### R3【落選級】「路線を止めたら？」の単位が利用者の考える「路線」と違う
- route_id ごとに全便を除いて再計算している。熊本は方向別（「桜町→通潤山荘」と逆方向が別の路線）。富山は同じ名前の路線が最大8つに分かれている（D_whatif.png のドロップダウン、「影響が大きい路線」ボタン）。
- 1つだけ止めても、同じ名前の兄弟の路線が残るため、影響は小さく出る。ドロップダウンでは見分けがつかない。
- 審査員の視点: 看板機能なので必ず触られる。「下赤江線が8つあるが、どれが何か」と聞かれて答えられない。路線を本当に止めたときの影響ではない。
- 対策: (事業者, 表示名) で路線をまとめて再計算する。少なくとも、表示名が同じ路線をまとめた選択肢を用意する。
- 失敗テスト: `test_whatif_route_labels_are_distinguishable`、画面 `whatif_toyama`

### D1【減点】地域を素早く切り替えると、表示とセレクトが食い違う（技術）
- `loadRegion` は、後から届いた応答で STATE.data を上書きする（whatif.js には同じ問題への対策があるが、app.js には無い）。回線の遅いスマホや会場のWi-Fiで起こる。
- 失敗テスト: aggressor_ui.mjs `region_switch_race`

### D2【減点】スマホの初期表示で結論が見えず、チェックボックスが小さい（UI/UX）
- 下のパネル（56vh）の中で、見出しの数字は 863px の位置にある（画面高 844px）。最初に見えるのは「タイトル・地域・条件ボタン」だけで、30秒で価値が伝わらない（B_mobile.png）。
- 表示切替のチェックボックスは高さ13px（ラベル全体は20px）。推奨の44pxより小さい。
- 横向き（844×390）では、パネルが画面の半分近くを占める（J_landscape.png）。使えなくはない。
- 対策: スマホでは見出しの数字（到達率）を、パネルの一番上か地図の上に固定して出す。

### D3【減点】凡例に塗りの色が無い。緑と赤は色覚の違いで見分けにくい（UI/UX）
- 塗りの意味（青／緑／赤／紫）は、サマリーの帯の説明と「路線を止めたら」の文中にしか出てこない。
- 緑 #2e9e5b と赤 #e0533d は、P型・D型の色覚では区別が難しい組み合わせ。主題（行ける／行けない）がこの2色の対比に乗っている。
- 地図は面積で赤が目立つ（人口の少ないメッシュが広い）。熊本は見出しで「83.5%が行ける」と出るのに、地図はほとんど赤に見える（A_desktop.png）。人口で透明度を変えるなどの工夫が必要。

### D4【減点】データの有効期間が審査期間の途中で切れる。期限切れの検出もない（技術・持続性）
- 熊本の4フィードは 2027-02-10〜12、喬木村は 2027-01-29 に切れる。表彰式（2/20）では、出典表の「データ有効期間」が過去の日付になる。
- 期限が切れても、`pick_ref_date` は期間内の最後の水曜を黙って使う。出力にも印が出ない。
- 締切（1/11）前に作り直すときは、--today に祝日・年末年始を避けた日を指定すること（D5）。
- 失敗テスト: `test_feeds_valid_through_award_ceremony`、`test_expired_feed_is_flagged`

### D5【減点】作り直す時期によっては、「平日」に年末年始・祝日のダイヤが入る（技術）
- 基準の水曜は calendar_dates の例外を見ずに決まる。年末（例 --today 2026-12-28 → 12/30）に作り直すと、平日ダイヤが運休の日を「平日」として診断する。
- 失敗テスト: `test_weekday_ref_avoids_exception_day`

### D6【減点】分母が「停留所から2km以内」なので、空白地の人が率から抜ける（社会課題）
- 「行ける人の割合」の分母は「収録した停留所から2km以内の人口メッシュ」。停留所から遠い、いちばん困っている人ほど分母に入らない。飯田のような疎な地域ほど率が高く出る。地域間の比較も公平でない。
- 生のメッシュがキャッシュに無いため、除外された人口は計測できなかった。作戦研究班は bbox 内の総人口と、診断範囲の人口の差を画面に出すこと（「範囲外 ○人」）。

### D7【減点】8:00ちょうどの一点で評価し、学校の診断の意味が弱い（社会課題・実用度）
- 出発は8:00／12:00／17:00の一点。2時間に1本の地域バスでは、7:58発を逃すかどうかで結果が裏返る。審査員（交通工学）は「時間帯の中で行ける出発時刻の割合」を期待しうる。
- 学校: 小学生は8:00に出て8:20〜9:00に着いても遅刻する。休日・昼・夕に学校へ行けるかの診断も意味が弱い。通学は学区で決まり、「最寄りの学校」ではない。
- 病院: 「病院」（国土数値情報 P04 の病院のみ）は診療所を含まない。通院の多くは診療所。帰りの便は評価していない（前提として記載あり）。

### D8【減点】作品名が「（仮称）」のまま（UI/UX・提出物）
- index.html の title・h1 と description.md が「生活アクセス診断マップ（仮称）」になっている。説明文は提出後に編集できない（S4）。

### D9【減点】名前の違う近接停留所の間で、徒歩の乗継ができない（技術）
- 統合の条件は「40m以内」または「同名で150m以内」。名前が違って60m離れた停留所（例: 市電の電停とバスの停留所）では乗り継げない。事業者間の乗継を売りにしているのに、取りこぼす。
- 失敗テスト: `test_walking_transfer_between_unmerged_stops`

### D10【減点】出典の規約確認が未了（規約）
- README は「e-Stat・国土数値情報の規約全文は取得・確認していない」と認めている。国土数値情報はデータごとに利用条件が違う。P04-20・P29-21 の条件（商用可否・クレジットの書式）を情報部が確認すること。
- e-Stat の推奨クレジット（URLと「加工して作成」）に、画面の文言を合わせる。

### 軽微
- `frequencies.txt` を無視する（テンプレートの1便だけになる）。現在の30フィードが使っているかは、キャッシュが無く未確認。使っていれば本数と到達を小さく見積もる。`test_frequencies_txt_is_expanded`
- 壊れたGTFSで、全地域のビルドが止まる: cp932 の文字コード（`UnicodeDecodeError`）、trips.txt の service_id 列の欠落（`KeyError`）、基準日に運行する便が0本の地域（`ZeroDivisionError`、center の計算）。現在のデータでは起きない。地域を追加するときに効く。
- feeds.json にフィードが無いと、ライセンス欄が空のまま出力される（出典表示の欠落を検出しない）。`test_feed_missing_from_repository_index_keeps_license`
- stops.txt の stop_id が重複すると、後の行で黙って上書きする。`test_duplicate_stop_id_is_detected`
- 有効期間が水曜を含まない短いフィードでは、基準日が期間の外になる。`test_ref_date_stays_inside_short_feed_period`
- 診断文字列が欠けたセル（データなし）を「到達できない」と表示する（lib.js cellStatus）。`fmtMin` は48時超を「翌」と表示する。
- CDN が遮断されると「maplibregl is not defined」と技術用語で出る。自治体の庁内ネットワークでは unpkg が遮断されることがある。MapLibre を web/ に同梱すれば解決する。
