# Haiku 初見ユーザー試験の改善ループ（odpt-teiji・sat-alpha・sat-a）2026-11-15

## 目的と方法
- 対象は、初回試験（`haiku-usertest-20261115.md`）で未達が多かった3アプリ。odpt-teiji は 0/10、sat-alpha は 2/10、sat-a は 5/10 だった。
- 1巡ごとに、各アプリへ Haiku を3体、1体ずつ順に起動した。渡したのは **URL・アプリの目的・目標** と共通ルール（`haiku-loop-20261115/RULES.md`）だけ。
- 3体の「使いにくい点・迷った点」をもとに参謀長が修正し、ビルドしてから次の巡に進めた。
- 前の試行者の記録（localStorage）を持ち越さないよう、試行者ごとに別のポートで `contests/dashboard/dist` を配信した。

## 主な修正（コミットは PR を参照）
- **odpt-teiji**
  - 路線を選ぶと、その路線の時間帯別の遅れと区間の上位に絞り込む。
  - 「区間あり」の路線を示し、区間のある路線へ1クリックで移れるボタンを置いた。
  - 選んだ路線のまとめとして、遅れやすい時間帯と、遅れが最も増える区間を出す。比べられる時間帯が1つしかないときは、そのことを但し書きで明記する。
  - 「未取得」「集計なし」「サンプル不足」を書き分け、用語の意味を画面に載せた。
- **sat-alpha**
  - 見直しの規則を変えた。区分ごとの要伐採の率を、見込みの率 50%（仮置き）と比べる。これで記録が1件でも点数が動く。
  - 「記録して、すぐ点数を見直す」ボタンを足し、④に移ったとき記録できたことを表示する。
  - 到達度の欄の候補を、②の計画の区間にした。確認結果の欄は初期値を空にして必須にした。
- **sat-a**
  - 区間ごとに調査結果を手で入力できるようにし、1区間から反映できると明記した。
  - 呼び方を「空洞の疑いあり／異常なし」「調査した」にそろえた。
  - 2回目の順位の比較基準を、文で示すようにした。
