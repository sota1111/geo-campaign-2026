## 中
### 中A （診断マップ・ダッシュボード版）地名検索が応答しないと、収録範囲内の駅でも「診断範囲外でした」と出る
- 場所: 13。東京都区部で例の「王子駅」を押し、地名検索の応答を保留させた。
  - 8秒後、「この場所で診断します（王子駅前（停留所））」と出て、地図も正しく移る。
  - ところがその下に「『王子駅前（停留所）』は診断範囲外でした。別の地域の『王子駅』かもしれません」と出る。
  - 「北区王子本町一丁目」と入れると、範囲内の停留所が4つ並び、どれにも「（診断範囲外）」が付く。
- 原因（参考）: index.tsx の doSearch。停留所名から探した候補は `inCell` を設定しないまま `rid: data.id` で追加している。そのため `first.rid === cur && !first.inCell` が常に真になる。また、停留所名で1件でも見つかると、「住所検索が応答しません…地図をタップ」の案内が出ない。
- なぜ問題か: 同じ枠の中で、表示が食い違う。例の駅のボタンは審査員が最初に押すものである。
- 直し方:
  1. 停留所名の候補にも `inCell: cellIdx[meshCodeAt(lon, lat)] != null` を付ける。
  2. 停留所名に切り替えた時は「住所検索が応答しないため、停留所名から探しました（『王子駅前』を選びました）。違う場合は地図をタップしてください」と出す。
  3. 数字や「丁目」を含む、住所らしい入力では、停留所名の部分一致で候補を並べない。

### 中B （診断マップ・単体版）地名検索が応答しないと「検索中…」のまま止まる（前回の中8と同じ）
- 場所: 17。15秒たっても「検索中…」のままだった。
- 原因: app.js:533 の fetch に時間制限がない。
- なぜ問題か: 単体版は ODPT の提出物そのものである。
- 直し方: ダッシュボード版と同じく8秒で打ち切り、「地図をタップ」の案内を出す。停留所名から探す代替を入れるなら、中Aの直し方を最初から反映する。

### 中C （不動産・印刷）いちばん長いケースで、本文がページ下端の余白ぎりぎりまで埋まる（要確認）
- 場所: 01（八万町・4問回答）。本文の下端は 828pt。A4 の高さ 842pt から @page の余白 6mm（約17pt）を引いた印刷範囲の下端は約825pt なので、余白がない。
- なぜ問題か: 確認できたのは Linux の Chrome（Noto 系のフォント）だけ。Windows や Mac ではフォントが違い、1行増えるだけで2ページになりうる。その場合、規約の段落はまるごと2ページ目に移る。
- 要確認:
  - A案（勧める）: もう3〜4行分詰める。例: 「データにない項目」と「ライブラリで確認する項目」を1段にまとめる。用語の説明を、シートに出た用語だけにする。
  - B案: Windows と Mac で印刷を確かめてから判断する。
