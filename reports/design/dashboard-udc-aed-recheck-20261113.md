#### N1. イチBiz タブの IN1 カードで、「デモを開く」ボタンがカードの枠からはみ出す。スマホではページ全体に横スクロールが出る（今回の修正による退行）

  - 390px: 図 m-portal-ichibiz-in1-crop.png。全体は図 m-portal-ichibiz-2026.png。
- 確かめたこと: 390px では `document.documentElement.scrollWidth` が 409。前回はどの画面も 390 だった。UDC タブは 390 のままで、退行はイチBiz タブだけに出る。カードの右の枠が画面の外に出て、ほかのカードの「開く →」も右端が少し切れる。
- なぜ問題か（レスポンシブ・視覚階層）: 前回の L2 で「ほかのカードと形をそろえる」ために直した箇所が、逆に崩れて見える。スマホでは、イチBiz タブ全体が左右に揺れる。
- 直し方: ボタンの文言は「デモを開く（UDC「夜も使えるAED診断マップ」）」で長く、折り返さない。どちらか1つで直る。
  - (a) ボタンは「デモを開く →」だけにする。どのアプリかは title とカードの本文（「UDC の「夜も使えるAED診断マップ」と共用」）で分かる。
  - (b) ボタンに `whitespace-normal h-auto max-w-full` を付け、CardFooter の中で折り返せるようにする。
  - 直したら、smoke の 390px の scrollWidth の確認に `#ichibiz-2026` を加える。

#### N2. 作品①（apps/odpt/）のヘッダーで、「出典・ライセンス」のボタンが右端で切れる（1280px。今回の修正による退行）
- 場所: 図 d-odpt.png の右上。「出典・ライセンス」は「出」の1文字しか見えない。左側のコンペ名も「ODPT／本応募（UD…」と省略される。
- 確かめたこと: header の scrollWidth は 1385、clientWidth は 1280。ヘッダーは `md:overflow-hidden` なので、はみ出した分が隠れる。今回足された「作品③（新案）「夜も使えるAED診断マップ」と見比べる」（幅 317px）がなければ、ヘッダーは約 1056px で 1280 に収まる。390px では折り返すので切れない（図 m-odpt.png）。
- なぜ問題か（データの扱い）: 「出典・ライセンス」は、出典とライセンスの全文を読む唯一の入口。作品①は本応募の作品でもある。地図の下にも出典の行があるので、出典がまったく見えなくなるわけではない。そのため中とした。
- 直し方: どれか1つ。
  - (a) 「見比べる」の2本（バス定時性カルテ・AED）を、1つのドロップダウン「新しい案と見比べる ▾」にまとめる。
  - (b) 文言を短くする（例「作品③ AED と見比べる」「バス定時性カルテと見比べる」）。
  - (c) md 幅でも `flex-wrap` を許し、ヘッダーを2行にする。この場合はページの高さの計算も合わせる。
  - 右端の「実データ」「出典・ライセンス」は `shrink-0` にして、切れる場合は左の補助リンクから省略されるようにする。

#### N3. ポップアップが開いたまま別の地点をタップ（クリック）すると、結果のポップアップが消えて出ない（M5 の残り）
- 場所: 埋め込み元の地図。スマホは図 m-night-tap.png → m-night-tap-top.png、デスクトップは図 d-night-click2.png。
- 確かめたこと（390×616、タッチ）:
  - 1回目のタップ: ポップアップが出る。
  - 2回目（ポップアップの外）: 印は新しい地点に動く。#gain-card の人数も 4,119人から 150人に変わる。しかし、ポップアップは閉じたままになる。
  - 3回目: 再びポップアップが出る。つまり、1回おきに結果が見えない。
  - デスクトップのクリックでも同じ。デスクトップの #gain-card は、パネルの top 1128px（画面の高さは 765px）にあって見えない。そのため、印が動くだけで何も起きないように見える。
- 原因の見立て: `maplibregl.Popup` は既定で `closeOnClick: true`。地図をクリックすると、アプリの click ハンドラが `addTo` した直後に、Popup 自身の close ハンドラが動いて閉じている。
- なぜ問題か（状態表示）: 候補地をいくつか試して比べるのが、この機能の使い方。2か所目の結果が見えないと、利用者は「壊れた」か「0人」と受け取る。
- 直し方（元アプリ側）: `new maplibregl.Popup({ closeButton: true, closeOnClick: false, maxWidth: "260px" })` にする。AED の点のポップアップも同じ Popup を使っているので、点をタップしたときも同じ挙動になる。手で閉じる手段は × で足りる。

### 軽微（見た目・一貫性）

#### N4. 「一般の人が使えない」四角が、「いま使える」大きい丸の上に重なって描かれる
- 場所: 図 d-night-overview-deuter.png の中央下（町田市の南の使える点）、図 d-night-click2.png の (1015, 404) 付近。同じ地点にあるAEDで、緑の丸の中に灰色の四角が載り、肝心の「使える」点が欠けて見える。
- 直し方: シンボルの層（aed-sym）を円の層（aed）より下に置く（`map.addLayer(..., "aed")` の beforeId を使う）。または、「使える」の円の層を最後に足す。

#### N5. スマホで IN1 の文書（.txt）を開くと、文字がとても小さい
- 場所: 図 m-in1-problem-txt.png。テキストファイルには viewport の指定がない。そのため、幅 980px として描かれ（scrollWidth 980）、文字は約 8px になる。ピンチで拡大すれば読める。文字化けは解消している。
- 直し方: 前回の H1 の案 (b) のとおり、`<meta name="viewport" content="width=device-width">` と `<meta charset="utf-8">` を付けた小さな .html で書き出すと、両方が一度に片付く。総司令官がスマホで読まないなら、このままでもよい。

#### N6. 帯の「戻ると IN1 のカードに着きます」が、実際とずれる。スマホでは帯が厚くなり、地図が狭い
- 場所: 図 d-aed-from-ichibiz.png、m-aed-from-ichibiz.png。
- 確かめたこと:
  - 戻り先は `#ichibiz-2026` で、タブの先頭に着く。IN1 カードは、デスクトップでは下へ約 900px、スマホでは約 1800px スクロールした先にある。
  - 390px では、帯が5行（作品③の注記を含む）になった。iframe は top 305px・高さ 492px で、パネル（55vh）を除くと、地図の見える高さは約 220px。前回は iframe が top 181px・高さ 616px だった。
- 直し方:
  - 文言を「戻るとイチBiz のタブに着きます」にする。または、戻り先を `#ichibiz-2026` のあとカードの id までスクロールさせる。
  - スマホでは、作品③の注記を `<details>`（「作品③の位置づけ ▸」）にたたむ。カードには同じ注記が全文で出ているので、帯は要約でよい。

## 良い点（直さずに残すべき点）

1. **点の区別の付け方。** 大きさ・形・縁の明るさの3つで分けており、2型・1型の模擬でも「使える」点がひと目で分かる。凡例の文言にも「大きい丸」「菱形」と形を書いている。色覚に頼らない見本として、ほかのアプリでもこの方式をそろえて使える。
2. **スマホのパネル開閉ボタン。** 「徒歩圏外 96%（月曜 03:00）　パネルを閉じる ▼」は、結論と状態と操作を1行で伝える。パネルを閉じて地図を広く見ている間も、結論が消えない。
3. **`?from=` で戻り先を切り替える仕組み。** どこから来たかを帯に1行で示し、戻り先も合わせている。未知の値は無視する。ほかのタブから共用デモを開く場合にも、そのまま使える。
