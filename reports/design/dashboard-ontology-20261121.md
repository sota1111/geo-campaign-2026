# デザイン審査: 統合ダッシュボード「つながり図」（ontology/index.html）

- 対象: `.claude/worktrees/agent-a6af0dddb59999f06`（ブランチ claude/engineer-ontology-ui-20261121、コミット 4340227）の contests/dashboard
- 確かめ方: `npm run build` → `npx vite preview --port 8865 --strictPort --host 127.0.0.1`（審査後に停止済み）。ヘッドレス Chrome（CDP）で 1280×800・1513×784・390×844 を撮影し、DOM の寸法・縮尺・タブ順を測定
- スクリーンショット: `reports/design/dashboard-ontology-20261121/`（20枚）
- 判断の軸: 総司令官が「何が何を止めているか」「次に誰が何をするか」「このデータが使えなければどこに響くか」をつながりで見て、次の一手を選べるか

## 結論
**重大 1・中 6・軽微 7**

「次の行動」の一覧とカードを使えば、3つの問いには答えられます。ただ、この画面の目玉である図が既定表示（69ノード）では読めません。図だけでは「何が何を止めているか」が分かりません。一覧からノードを選んだときに視点が飛ぶ問題もあり、図と一覧の連動はまだ弱い状態です。

## 重大（目的達成を妨げる）

### 重大-1 既定表示の図が読めず、「何が何を止めているか」を図から読み取れない
- 根拠:
  - `d1280-01-default.png` の図の領域全体。React Flow の縮尺は 0.579 で、ノード名 12px は実際に約7px、種類名 11px は約6.4px で表示されている
  - 69ノードのうち50ノードで、名前が2行に収まらず途中で切れている（`line-clamp-2` の span で scrollHeight > clientHeight を実測）。3行目の上半分だけが見える、読めない帯になっている
  - 109本の線が、右端の「アプリ・案」の列から左の「応募」の列まで、2列ある「止めているもの」の上を横切っている。どの指摘がどの応募を止めているかを線で追えない
  - 応募ノードに状態（×提出不可／△要修正あり）が出ていない。指摘ノードにも重さが出ていない（状態は aria-label にだけある）。17件の提出不可と2件の要修正ありを図の上で区別できない
  - `d1513-01-default.png`（1513×784）も縮尺 0.62 で同じ状態
  - `m390-01-default.png`（390×844）は縮尺が 0.4 で止まる。そのため左端の「コンペ」と右端の「アプリ・案」の列が枠の外に切れ、コンペとアプリが1つも見えない
- なぜ問題か: 第一画面の3秒テストと視覚階層の観点。この画面の目的は「つながりで見る」ことだが、既定表示の図はほぼ模様にしか見えない。結局、利用者は左の文字の一覧とカードに頼るしかない。カードの内容は図がなくても読めるので、図を足した意味が初見で伝わらない。一方、ノードを1つ選んで「近傍だけ表示」にすると（`d1280-14-focus-sub.png`）縮尺1で関係がよく読めるので、問題は既定表示の密度と縮尺にある
- 直し方の提案（どれか1つで重大は解消。組み合わせるとよい）:
  1. 既定表示を「応募ごとのレーン」にする。1行に「コンペ ← 応募（状態つき）→ その応募を止めているもの」を横に並べ、アプリは応募ノードの中に名前として含める。こうすればアプリの列へ戻る長い線が消える
  2. 既定で出すものを絞る（例: 締切が最も近いコンペの応募と、その失格級・欠落だけ）。そのうえで、文字が実寸 11px 以上になる縮尺（約0.9以上）で始める。他のコンペは上部の切り替えで出す
  3. 応募ノードに状態の記号と言葉（「× 提出不可」「△ 要修正あり」）を、指摘ノードに重さ（「失格級」）を、ノードの中に文字で出す
  4. スマホでは図を既定で「選んだノードの近傍だけ」にする。全体図はボタンで開く
- 備考: 交戦規定では、目的達成を妨げる問題は reports/escalations/ にも記録することになっている。ただ、審査班の書き込み範囲は reports/design/ だけなので、エスカレーションは記録していない。必要なら参謀長の判断で記録してほしい。

## 中（迷い・手戻りを生む）

### 中-1 「次の行動」を押すと、押した一覧がカードに押し出されて見失う（スマホでは押した結果も見えない）
- 根拠:
  - `d1280-03-next-sub-click.png`: 応募を押すと、左の列の先頭に高さ 646px のカードが差し込まれる。押した「次の行動」の一覧は画面の外へ押し下げられる。2件目、3件目と順に見ていくたびに、左の列を戻すスクロールが必要になる
  - `d1280-07-impact.png`: 「データが使えなければ」のタブでデータを選ぶと、カードが差し込まれる。いま操作した選択欄が画面の外へ消え、別のデータを選び直せない。さらに「もし〜が使えなければ、響くもの」の紫の枠が、カードとタブの2か所に同じ内容で出る（DOM 上も `impact-list` が2つある）
  - `m390-06-after-tap.png`（390px で2件目の応募を実際にタップした結果）: スクロール位置は変わらない。カードの見出しは画面の上に切れ（top −85px）、図は 672px 上の画面外にある。何が選ばれたか、図のどこかが見えない
- なぜ問題か: 状態表示とスクロールの観点（自動で位置が動いて位置を見失う）。さらに「押すと図でその応募を選びます」という案内どおりの結果が目に入らない
- 直し方: カードを一覧の上に差し込まず、場所を固定する。デスクトップなら図の右側か図の上に重ねるパネル、スマホならボトムシートにする。または左の列を「カード」と「次の行動」のタブに分ける。データのタブで選んだときは、カードを開かずタブの中の結果だけにして、重複を消す。スマホで選んだときは、図とカードの見出しが見える位置まで動かす

### 中-2 キーボードのタブ順が見た目と逆で、一覧から選んでもカードが見えない
- 根拠:
  - タブ順を実測した。「図を飛ばして」の次は、図の中の69ノードのボタンに入る（最初は右端の「アプリ・案: バス路線見直し案の比較」）。見た目で先にある左の列（カード・次の行動）に届くのは30個目以降。図の中には止まる場所が73か所あり、並び順はノードの登録順で、図の上の位置とは無関係
  - スキップリンク「図を飛ばして、ノードの一覧へ」（`d1280-09-kbd-skiplink.png` のヘッダー直後）の飛び先は、左の列の最下部にある一覧。「次の行動」も飛ばしてしまう
  - `d1280-10-kbd-list-select.png`: 一覧で Enter を押すとノードは選ばれる。しかしカードは左の列の約 4,600px 上（rect.top −4605）に出て、画面にもフォーカスにも現れない
- なぜ問題か: アクセシビリティ（キーボード操作）と状態表示の観点。キーボードでは「選んだ結果」を確かめられない
- 直し方: DOM 順を左の列が先になるようにする（スマホで図を先頭に出すのは CSS の order で行う）。図の中のノードのボタンは tabIndex=-1 にし、キーボードでは一覧から選ぶ前提にする（aria-label に既に書いてある方針と一致する）。スキップリンクの飛び先を「次の行動」にし、一覧へのリンクは別に設ける。選んだらカードの見出しへフォーカスを移す（または aria-live で「〜を選びました」と知らせる）

### 中-3 「データが使えなければ」で、影響の大半が図の外にあり、応募の件数も水増しされている
- 根拠:
  - `d1280-07-impact.png`: 「国土数値情報 都市公園 P13」を選ぶと、図は縮尺1でデータのノードへ寄る。影響を受ける3件（アプリ・応募・コンペ）のうち、画面に見えるのはアプリ1件だけ。全体表示ボタンを押してようやく3件の紫の枠が見えるが、その縮尺では読めない（`d1280-08-impact-fit.png`）
  - 同じ画面の紫の枠に「応募（2件）」とあり、同じ「子連れお出かけ診断 → 公共交通オープンデータチャレンジ2026」が2行並ぶ。next-actions.json の `dataImpactAll` を調べると、34データのうち17データで、同じ応募 id が重複している（例: 地理院タイルは21行あるが実際は16件、e-Stat は10行で実際は7件）
- なぜ問題か: 状態表示とデータの扱いの観点。「どこに響くか」という問いに対して、図では一部しか見えず、一覧では件数を多く見せている
- 直し方: 影響を選んだら、データと影響を受けるノードの全部が入るように寄せる（`fitView({nodes:[データ, ...影響]})`）。または影響の強調中は自動で「近傍だけ表示」にする。応募の一覧は id で重複を除く（生成側 ui_json.py／next_actions.py で除くのが正しい。工兵に確認を依頼）

### 中-4 デスクトップで図の下端と拡大縮小ボタンが画面外になり、ページと左の列でスクロールが二重になる
- 根拠: 1280×800 で図の枠の下端は y=840、操作ボタンの下端は y=823。「全体表示」のボタンは初期表示で見えない（`d1280-01-default.png` の左下）。ページの高さは 1041px で縦スクロールが出る。左の列にも別のスクロールバーがある（内容 4,210px）。1513×784 でも図の下端は y=808 で同じ（`d1513-01-default.png`）
- なぜ問題か: スクロールの観点（デスクトップで不要なページスクロールがある）
- 直し方: 図の高さを `calc(100vh - ヘッダー - 見出し部)` から実寸で計算する。または見出しの説明文（2〜3行）を折りたたんで、ページを 100vh に収める。操作ボタンは右上へ移す

### 中-5 凡例が初期表示で見えず、図の案内文が実際の配置と食い違う
- 根拠:
  - 凡例を兼ねる「図に出す種類」は、左の列の中で約 2,636px 下にある（`d1280-11-legend.png` はそこまでスクロールした状態）。初見では、赤・緑・紺の箱が何を表すのか図の近くでは分からない
  - 図の下の案内は「右下の＋－ボタン」だが、ボタンは左下にある（`d1280-01-default.png` の左下、実測で x=437）
  - 見出しの「下の『図に出す種類』で足せます」も、デスクトップでは左の列の下のほう（別スクロール）にある
- なぜ問題か: 文言の観点（配置に依存する案内が実際と違う）と第一画面の観点（何が描かれているか）
- 直し方: 図の枠の上辺に、6つのまとまりの色・記号・言葉を1行で並べた小さな凡例を常に出す。線は「矢印は から → へ」と書く。チェックボックスは今の位置のままでよい。案内文は「左下の＋－」に直す。「下の」は「左の列の『図に出す種類』」に直す

### 中-6 「止めているもの」の件数が場所によって違う
- 根拠: 同じ応募（路面下リスクの二段階調査 → 衛星）について、次の行動では「止めているもの（4件）」、カードのつながりでは「→ 止めているもの（9）」と出る。カード本文では「止めているもの: 失格級3・要修正5・未記入欄ファイル1・データ条件0」（合計9）になっている（`d1280-03-next-sub-click.png` の左の列、`d1280-01-default.png` の一覧）
- なぜ問題か: 一貫性の観点（同じ言葉に違う数）。次の行動のほうは要修正を除いた数だが、その説明がない
- 直し方: 次の行動のほうを「提出を止めているもの（失格級・欠落など 4件）」とし、カードの見出しを「指摘・欠落（9）」のように言葉で分ける。少なくとも、次の行動に「要修正は除く」と書き添える

## 軽微（見た目・一貫性）

1. カードの「閉じる」ボタンが「閉じ／る」の2行に折り返す（`d1280-03-next-sub-click.png` の右上、`m390-04-card.png`）。`whitespace-nowrap` を付ける。
2. 選んだノードの線の名前が重なる。「止めているもの」が3つ重なり、「影響を受けるアプリ」がノードに被って「響を受けるアプリ」と読める（`d1280-03`、`d1280-14-focus-sub.png`）。同じ名前の線はまとめて1つだけ名前を出すか、名前を線の中ほどからずらす。
3. 応募のカードで、同じアプリが「→ 案（1）」と「← 応募（1）」の2群に重ねて出る（`d1280-03` の左の列）。逆向きの同じ関係はまとめる。
4. コンペのカードに、締切・応募数・提出可否の要約がない。つながり（76件）とリンクだけが出る。ポータルのコンペカードと同じく「次の締切・あと何日・判断待ち」を出すと、「次の一手」を選びやすい。
5. 検索が0件のとき「0件が見つかりました（先頭 80 件まで）。押すと選び、図にも足します」と出る。「見つかりません。言い換えるか種類名（例: 失格級）で探してください」とする。
6. ヘッダーで、いま見ているのが「つながり図」かどうかの区別がない（aria-current なし、見た目も同じ）。また、この変更で「提出状況は 11/21 時点の記録」の表示条件が sm 以上から lg 以上に変わり、640〜1023px で消える。ポータルの構成の変化はこの1点とリンクの追加だけ（`d1280-12-portal.png`、`m390-07-portal.png`。本文のコンペカードとアプリ一覧は従来どおり）。
7. 390px で、カード内の「つながっている相手」のリンクや一覧の下線ボタンの高さが約16px しかない（高さか幅が24px 未満のタップ対象が68個）。`min-h-7` 程度を付ける。

## 良い点（直さずに残してほしい）

1. **色に頼らないノードの表現**: 色のまとまりに加えて、形（楕円・二重線・破線など）・記号（◆▣!?∅★）・種類の言葉を重ねている。凡例がそのまま出し入れのチェックボックスを兼ねている（`d1280-11-legend.png`）。影響の強調も「影響」の札と紫の枠で、色だけに頼っていない。
2. **「近傍だけ表示」**: 1つの指摘が2つの応募を止め、2つのアプリに響くことが、縮尺1で一目で読める（`d1280-14-focus-sub.png`）。この画面で一番価値のある見え方なので、既定表示を改めるときの手本にしてほしい。
3. **総司令官の判断の一貫した表示**: ★と黄色の注意書きで「この画面からは進めない」ことを、見出し・カード・判断待ちのタブで同じ言葉で示している。判断待ち18件には締切と出典が付いている（`d1280-04-gates-tab.png`、`d1280-05-gate-selected.png`）。
