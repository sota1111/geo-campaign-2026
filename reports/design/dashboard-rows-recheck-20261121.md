## 軽微（見た目・一貫性）

### K1. （M1 の残り）1280×800・1024×768 の第一画面にアプリ名が入らない
- 画面: `1280-01-first.png` の下端（順位バッジだけ見える）、`1024-01-first.png`（アプリ見出しと下書き欄まで）
- 観点: 第一画面・スクロール。並べ替えた結果と1位の名前は文で見えるようになったので、目的の達成は妨げないと判断して軽微に下げた
- 直し方: 見出しとカードの間にある下書き欄（高さ約 110px。「この選択はこのブラウザだけの下書き…」・JSON ボタン・使い方）を、アプリの行の下へ移すか1行に畳む。1280×800 でカードの名前と目的（上端から約 120px）が画面に入る

### K2. 失格級の注意（C3: 衛星に B と α を両方）が、ほかの注意（C4・C5）と同じ見た目
- 画面: `1280-05-after-select.png`（盛土巡視台帳・配電線のカード下部。C3・C4・C5 はどれも同じ琥珀色の枠）
- 観点: 視覚階層。1行目に「（同時提出は失格級）」と書いてあり、選択は下書きで提出前に憲兵の監査もあるので軽微。ただ総司令官の優先順位は「失格しないこと」が一番
- 直し方: 失格級の注意だけ、先頭に置き、枠を太く・濃い色にし、「失格級」の文字バッジを付ける（色だけに頼らない）

### K3. 1枚に注意が出ると、18枚すべてのカードが同じ高さまで伸びる
- 画面: `1280-05b-after-select-full.png`（注意のないカードの下に約 220px の空白）。押した位置はずれないので（M2 解消）軽微
- 直し方: 行を `items-start` にしてカードごとの高さにする。またはそのままでよい（そろった高さを優先するなら好みの問題）

### K4. 「18件中 m〜k件目」が role="status" で、横スクロールのたびに読み上げられる
- 画面: `1280-07-filter.png` の位置表示。コード上 ScrollRow の span に role="status" が付いていて、onScroll ごとに中身が変わる
- 観点: アクセシビリティ（スクリーンリーダーで、スクロール中に読み上げが続く）
- 直し方: 位置表示から role="status" を外す。絞り込みの件数（「2件に絞りました」）は role="status" のままでよい

### K5. アプリの行で Home/End が効かない
- 計測: 行にフォーカスして End → scrollLeft は 0 のまま。右矢印では 300px 動き、位置表示も「2〜6件目」に変わる。絞り込みがあるので任意
- 直し方: 行の onKeyDown で Home/End に scrollTo(0 / scrollWidth) を付ける

### K6. 390px で、まだ 44px に届かない押す場所がある
- 計測（390×844）: 「選べない理由」「判定の理由と出典」の summary は 28px、「前へ」「次へ」と「このコンペで並べる」は 36px、アプリ名のリンクは 19px（行の高さ）
- 直し方: 390px では summary とボタンを `min-h-11` にする。アプリ名のリンクは `py-2` で押す場所を広げる

### K7. 390px のアプリのページ（sat-b）の本文が「左の『参考（任意）』の手順」と言うが、390px では左にリストはなく、上の「手順 1／6」バーの中にある
- 画面: `app-sat-b-390.png`（本文の「左の」と、上の「手順 1／6：データを確かめる 0/6 完了 ∨」バー）
- 観点: 文言（配置に依存する案内）。前回 390 は「バーがあるので影響なし」としたが、文言は合っていない。今回の変更によるものではない
- 直し方: 「手順リストの『参考（任意）』」のように、配置に依存しない言い方にする（sat-a も同じ書き方があれば合わせる）
