## 重大（目的の達成を妨げる）

### S1. 1024×768 では、コンペカード4枚とも審査基準と提出予定がまったく見えない。概要も行の途中で切れる
- 画面: `01-top-1024x768.png`・`09-sort-ichibiz-1024x768.png`。4枚とも「次の締切 → 賞金（2〜3行）→ 内訳ボタン（1行を使う）→ ▲判断待ち → 概要」の順に並ぶ。概要は1行目の下半分が切れて見える（イチBiz は 4px しか見えず、「概要」という見出しも読めない）。審査基準と提出予定（今回足した行）は 0px で、まったく見えない。報告にあった「切れ」はこれ
- 原因（計測から）: 行を減らしていく仕組み（`cardPlan`）を最後の段まで使っても入りきらない。賞金の行が折り返して 42〜60px を使い、「内訳」ボタンが行の外に押し出されて1行を使っている。イチBiz では締切の「（ビジネス部門）」も折り返す。最後の段でも概要は `hideSummary: false` なので消えはしない。ただ `overflow-hidden` の外へ押し出され、行の途中で切れる
- 観点: 視覚階層。総司令官の意図「コンペカードは概要と審査基準を優先」に、指定のサイズで反している。後から足した賞金が、優先すべき概要と審査基準を画面の外へ押し出している
- 直し方:
  1. 1280px 未満では賞金の行を「賞金 最高300万円 [内訳]」の1行にする（`truncate`、要約の文は短い形にする）。あるいは賞金を見出しの帯へ移し、「賞金▸」で開くようにする。どちらでも内訳ボタンが別の行に落ちないようにする
  2. 締切の補足「（ビジネス部門）」などは、1280px 未満で `title` へ移す
  3. 入りきらないときに減らす順番を「提出予定の部門ごとの行 → 賞金の要約 → 判断待ちの行 → 提出予定の合計」とし、概要（2行）と審査基準（1行）は最後まで残す
  4. 受け入れの条件: 1024×768 で、4枚とも `card-summary` と `card-criteria` が 1px 以上切れない（下の計測と同じ方法で確かめる）

### M2. 予定数の記号 ▼✓▲ の意味が凡例になく、▲ がほかの意味と重なっている。短い形「▼あと1」には単位がない
- 画面: `01-top-1513x784.png`。同じカードの中で「▲ 判断待ち（提出不可）」と「▼あと2件で予定」が上下に並ぶ。▲ と ▼ が対になって見え、増減や並べ替えの矢印のように読める。アプリ行の上の凡例「記号: ◎…○…△…×…？…／✓ 選んだ提出先」には ▼ と ▲ の説明がない
- 意味の重なり（コードと画面で確かめた）: ▲ は「判断待ち（提出不可）」（コンペカード）、「注意」（アプリカード・下の行）、「予定より N件多い」（`fit.ts` の over）の3つの意味で使われている。✓ は凡例で「選んだ提出先」の意味なのに、予定数では「予定どおり」の意味で使っている
- イチBiz の部門ごとの行は「▼あと1」と短くしてあり、「あと1件選ぶ」なのか「残り1日」なのかが読み取れない（`PlanCount.tsx` の `short` で「件」と「で予定」を取り除いている）
- ▼ の色は amber-950 で、本文の黒とほとんど区別がつかない（色に頼らない点はよい）
- 観点: 一貫性・文言
- 直し方: 予定数には三角を使わない。言葉を先に出す（例「あと2件」「予定どおり」「1件多い」）。記号を残すなら、予定数専用のもの（例「不足」「達成」「超過」の札）にして、▲ は「判断待ち・注意」だけに使う。部門ごとの行も「あと1件」と単位を残す。凡例に1語で足す（「予定数: あと N件／予定どおり／N件多い」）
