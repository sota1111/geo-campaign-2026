# 評価報告

## 総評
道路調査、生活アクセス、バス定時性の主要な結論と操作は確認できた。盛土は造成地と写真を確認し通報文もコピーできたが、写真の差を実際の変化と断定できず、記録の分類も不適切なままになった。
生活アクセスの共有リンクは localhost であり、遠方の家族がそのまま開ける公開リンクではないと画面に明記されていた。

## 迷った点・不明点

時間は操作中の体感による概算で、厳密な計測ではない。

### 路面下リスクの二段階調査
- **低**／候補区間一覧／最高点を一つ特定しようとしたところ、0.94が3区間同点で、表の1位だけを答えると他の同点を見落としそうになった。最高点カードを見直して3区間と表の1位を併記した。約10秒。改善案：一覧上にも「同点1位」を表示する。
- **低**／予算選択／最初は個別チェックを選び、上位から一括選択できる場所を探した。3区間を手動選択して進んだ。約15秒。改善案：一括選択を選択数・予算のすぐ横に置く。

### 生活アクセス診断マップ
- **中**／結論画面／「病院に行ける」が実際の診療を受けられることまで意味するか一瞬迷った。詳しい根拠と注意書きを読み、徒歩到達の推計で診療時間・予約は未確認と理解した。約15秒。改善案：結論の直下に「到達可能性の推計、診療は要確認」を目立つように置く。
- **中**／家族に送る画面／コピーしたリンクを遠方の兄が開けるか確認したところ、localhostの確認アドレスだった。画面下の注意を読んで公開後のアドレスが必要と理解した。約15秒。改善案：公開前は共有ボタン付近に「このリンクは他の端末では開けません」と明示する。

### バス定時性カルテ
- **中**／右上の「出典・ライセンス」／データ提供元を探したが、表示は元の静的版の画面内「出典」欄と README を参照する案内で、その場に提供元はなかった。ダイアログを閉じて右パネルを下までスクロールし、公共交通オープンデータセンターを確認した。約25秒。改善案：ダイアログ自体に提供元とライセンスを直接表示し、画面内の該当箇所へ移動できるようにする。
- **低**／事業者欄／初期選択のきよバスが自社の選択例として使えるか確認した。「データ蓄積前」と明示されているためそのまま状態を読んだ。約10秒。改善案：選択欄の直近に観測期間と集計可否をまとめる。

### みんなの盛土ウォッチ
- **中**／昔の写真と見比べる／建物の変化を確かめたかったが、古い写真と最新写真の画質や明るさが異なり、境界内の差が実際の変化なのか判別しづらかった。見え方の違いとして記録し、未確認と記した。約40秒。改善案：左右同時表示の案内と、解像度・撮影条件の差による判断限界を写真の直近に強調する。
- **高**／台帳に記録を足す「気づいたこと」／写真の見え方の違いを記録したかったが、初期値が「亀裂・段差」で、適切な分類を選べたか確認できず、そのまま保存してしまった。一度削除して再入力したが選択変更を確認できず、メモに「亀裂は確認していない」と明記した。約60秒。改善案：初期値を未選択にし、「航空写真の変化・その他」を明示、保存前に分類とメモの矛盾を確認できるようにする。操作環境固有の選択操作の問題もあり、アプリの不具合とは断定しない。
- **低**／トップの左側一覧／「みんなの盛土ウォッチ」を探す際、一覧スクロール位置が戻り、一度別の太陽光アプリを開いた。戻って一覧を再度スクロールした。約20秒。改善案：戻ったとき一覧の位置を保持し、コンペ名や用途で絞れるようにする。

## 不具合
確実にアプリの不具合と断定できたものはない。上記の分類選択はヘッドレス環境の操作も影響しうるため、再現性を確認できていない。再確認手順：熱海駅の例→近くの造成地→写真比較→台帳に記録→地図を選択→「気づいたこと」を開き、別の分類を選択して保存し、台帳と通報文に反映されるか確認する。

## 確認できなかった範囲
- 生活アクセスのリンクを別端末で開くこと、実際の病院の診療時間・予約・運行実績は確認していない。住所検索は大町の代表地点であり実際の自宅ではない。
- バスの蓄積後の集計、他事業者、他の時間帯の実測は確認していない。
- 盛土の現地状況や実際の変化は確認していない。通報文はコピーしただけで送信していない。テスト記録はブラウザ内保存で、終了時の一時プロファイル削除により消える。
- 所要時間は概算。サーバーは停止・再起動していない。
