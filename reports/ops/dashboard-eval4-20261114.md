# 統合ダッシュボード 第4回評価（sol・terra・luna 各10回）と改善（2026-11-14 参謀長）

## 方法
- 評価者: codex CLI の GPT-6.1 sol／GPT-6.1 terra／GPT-6 luna（reasoning effort low）。
- 回数: 全12アプリを3組（g1: #1・#12・#2・#3／g2: #4・#8・#5・#9／g3: #6・#11・#7・#10）に分け、モデル×組ごとに10回、計90回。各アプリを各モデルが10回評価した。担当の順は回ごとに回した。
- 伝えたもの: 使用目的・目標の成果（reports/ops/dashboard-goals-20261111.md・-20261113.md の G1〜G12）・ダッシュボードのトップURL（main 最新をビルドして 127.0.0.1:8850 で配信）。ソース・README・reports の閲覧は禁止。
- 第3回との違い: 採点（A・B・C）はやめ、目標の達成と「迷った点・不明点」（重さ 高・中・低、場所、改善の提案）を主な成果物にした。
- 生データ: reports/ops/dashboard-eval4-20261114/<model>-<組>-<回>.md・.json。スクリーンショット（約1,100枚・626MB）と評価者のブラウザプロファイルは容量のため git に入れていない（参謀長の作業領域に保管。md 中の画像名はその控え）。

## 迷った点の主な傾向と、行った改善
迷った点は集計できた88回で725件（高 73・中 470・低 182）。同じ指摘が3回以上出たものを優先した。

| アプリ | 繰り返し出た迷い（回数の目安） | 改善 |
|---|---|---|
| 共通 | 手順を替えると前の手順のスクロール位置が残り上部の操作が隠れる（sat-a 8回）。手順が済むとサイドバーの項目が縮み、次の項目を押し間違える（sat-b・biz-business・realestate 計10回）。確定しても画面が切り替わらず次の操作を探す（biz-business 7回・sat-b 3回） | 手順を替えたら本文を先頭へ（スマホは見出しへ）。サイドバーの説明は済んだ後も出して高さを保つ。操作で済む手順は、済んだら見出しの下に「次の手順へ進む」を出す |
| ポータル | 目的のアプリが左一覧の下に隠れ、名前だけでは似たアプリ（盛土巡視台帳／盛土ウォッチ、路線見直し／定時性）を見分けられない（約15回） | 左一覧の上に「目的・地名からアプリを探す」絞り込み欄。各アプリに目的を1〜2行表示 |
