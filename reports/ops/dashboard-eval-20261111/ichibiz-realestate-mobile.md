# 評価報告: ポータル（スマホ幅重点）＋ イチBiz不動産「相談前の1枚シート」（2026-11-11 評価者）

評価方法の注記
- Claude in Chrome で自分用タブを作成。resize_window は成功と返ったが実際の innerWidth は変わらなかったため、ポータルとアプリを幅390px・高さ844pxの同一オリジン iframe に読み込み、メディアクエリが働くスマホ幅の表示として操作・確認した（実機のタッチ・アドレスバーは未検証）。ウィンドウサイズは変更していない。
- 途中でタブグループが閉じられたため、自分のタブを作り直して実行サンプルとタップ寸法の確認を行った。タブは最後に閉じた。
- 印刷ボタンは押していない（存在と説明のみ確認）。キーボード（Tab/Enter）操作はアプリ側では未検証。

## 1. 総評
- ポータルは「締切・注意点・未確認」が色と文言で分かれ、審査基準の「確定」と「例示」の区別も明確。スマホ幅でも崩れず読めるが、1ページ約2300pxと長く、目的アプリ（ページ末尾）まで約1500px のスクロールが要る。
- 1枚シートは、場所→質問→条件→「聞くこと」→印刷の手順が明快で、実データと「測量ではない」等の限界表示が誠実。一方、手順の「次へ」ボタンがなく、スマホでは地図が常に画面の約35%を占める。
- 不動産部門の要件である「不動産情報ライブラリ」の活用が、画面のどこにも書かれていない（ポータルは「活用する不動産情報ライブラリの情報を書く」と要求）。審査上の最大の弱点。

## 3. 改善提案
- 高: 不動産情報ライブラリの活用を画面で明示する。出典・ライセンスと手順3に「不動産情報ライブラリ（国土交通省）」を載せ、どの項目（用途地域・ハザード等）がそこ由来かを示す。可能なら取引価格・地価公示・将来推計人口など「取得していません」としている項目を実際に取り込み、条件欄・聞くことに反映する。取り込めないなら、ポータルの要項説明と整合する形で、使った情報を書く欄を用意する。
- 高: アプリ内に「次へ」ボタンを置く。各手順の末尾（質問の下・条件一覧の下）に「次: 手順 n」の主ボタンを固定表示し、現在は折りたたみバーを開かないと進めない状態を解消する。
- 高: スマホで目的アプリに着くまでの距離を縮める。ポータルのコンペタブ選択後、アプリカードを締切・提出物の上、または「このコンペのアプリ」への固定リンクを上部に置く（現状は約1500pxスクロール）。
- 中: アプリの冒頭に1行で「誰が・何のために」（例: 相続した土地の所有者が相談前に1枚にまとめる）を表示。ヘッダ題名がスマホで「相談…」に省略されるのも直す。
- 中: スマホの手順4・5で地図を小さく／折りたたみ可能にし、手順5のシートはプレビューの入れ子スクロールをやめて全幅で表示。
- 中: 持続性の見せ方（誰が更新・運用するか、対象市町村の広げ方、データ更新）を、ポータルまたはアプリ内の説明に加える（C-BIZ4）。
- 低: 手順5を開いたとき進捗が「4/5」のまま。印刷操作後に5/5にするか、「印刷で完了」と書く。
- 低: ポータルの最小文字10pxの箇所、カード説明の省略（…）を見直し、締切の重複表示を減らす。

## 4. 迷った箇所・不具合
1. 手順間の移動: 手順1で土地を決めた後、画面に「次へ」が無い。ヘッダの「手順 1／5」バーをタップして5項目のリストを開き、手順2を選ぶ必要があった。再現: アプリを開く→「徳島駅」で検索→「この位置を…使う」→（次の操作が分からない）。
2. 取得待ち: 「この位置を…使う」の後、「公開データを集めています…」が数秒続き、終わっても進捗数字の変化以外の通知はない。
3. 手順5の進捗: 手順5を開いても「4/5」。
4. 実行サンプルの文言とスマホ表示の不一致: 手順5の「AIが模擬利用でしたこと」は「右側にA4・1枚相当のシートのプレビューが出た」とあるが、スマホ幅ではシートは右ではなく上に表示される。
5. 計測: ポータルのスマホ幅で、「Toggle Sidebar」が28×28px、UDCの公式リンクが高さ約16pxと小さい（タップしにくい）。
6. ブラウザの resize_window が効かなかった（環境側の事象）。

## 5. ポータルの記載とアプリの内容の食い違い
- ポータル「不動産情報活用部門だけ、活用する不動産情報ライブラリの情報を書く」に対し、アプリ内に不動産情報ライブラリの記載・使用が見当たらない（上記）。
- ポータルのカード説明「土地の条件と聞くべきことを1枚にまとめる」は、アプリの手順5の内容と一致。ポータルの「一部架空」バッジもアプリに同じ表記あり。その他の食い違いは見つからなかった。
