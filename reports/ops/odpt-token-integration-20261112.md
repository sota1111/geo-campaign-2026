# ODPTセンター トークン必須データの取り込み（odpt-2026 / UDC2026①）— 2026-11-12 工兵

対象: contests/odpt-2026/app（静的版）と contests/dashboard/src/apps/odpt（ダッシュボード版）。弱点 R2（東京で JR・東京メトロ等が「鉄道駅が近い（未評価）」）への対処。

## 結論
- 東京メトロ・りんかい線・つくばエクスプレス（鉄道3）と、関東・京王・西武・小田急バス、区のコミュニティバス6データを追加。東京の ODPTセンター由来データは 2 → 15 になった。
- 東京の「未評価」（病院・平日朝・20分）は、改修前と同じ1,737メッシュで比べて **205,645人 → 81,667人（-60%）**、30分では **44,602人 → 9,860人（-78%）** に減った。
- **残りの未評価は JR・東急・西武・京王・小田急・京急・東武・京成・ゆりかもめ等の駅の周り**。これらの GTFS／時刻表は ODPTセンターでは「公共交通オープンデータチャレンジ限定ライセンス」しか無く、UDC にも出す本作品には組み込めない（下記）。R2 を完全に解くことは、ライセンス上できない。

### 再配布可否の判断（基本ライセンス本文。developer.odpt.org の規約ページのJSから本文を取得して確認）
- 第4条1項: 基本ライセンスデータで成果物を作成し、一般に公開して一般ユーザに利用させてよい。営利・非営利を問わない（同7項）。
- 第8条4項(1): 元データの「全部または大部分を復元可能」な派生データを、第三者が再利用可能な状態で公開・再配布することは禁止。
  - web/data に置くのは、停留所群の位置と名称、時間帯別の便数と始発・終発、路線名と停車順、メッシュごとの診断結果まで。個々の便の時刻表（stop_times）は含まないので、元の GTFS は復元できない。よって「成果物の一部」として置いてよいと判断した。**この判断は工兵によるもの。憲兵・情報部の確認を推奨する。**
- 第4条2項(4): データが更新されたら成果物を直ちに更新すること → 運用の課題（未解決事項を参照）。
- 開発者ガイドライン: 公開時に一般ユーザへ次の3点を通知する必要がある。①ODPTセンター提供であること ②正確性・完全性を保証しないこと ③問い合わせ先（開発者のメールアドレス等）を示し、事業者へ直接問い合わせさせないこと。①②と「事業者へ直接問い合わせないでください」は出典欄に追加した（`ODPT_NOTICE`）。**③の開発者メールアドレスは未記載（下記）。**

## 東京地域の「未評価」の改修前後
集計は lib.js の `cellStatus` と同じ規則。改修前は改修後と同じキャッシュでトークンなしでビルドしたもの（コミット済みの tokyo.json と全数値が一致）。

小・中学校・平日朝・20分の未評価（同じ1,737メッシュ）: 66,424 → 26,457。
鉄道駅の印が付くメッシュ（同じ1,737メッシュ）: 1,310 → 1,061。地図上の「未収録の鉄道駅」: 435 → 281駅。

読み方:
- 「行けない」が増えたのは、これまで灰色で保留していた東京メトロ駅の周りを評価できるようになり、20分以内には着けないと分かった地区が出たため。数字が悪化したのではなく、未評価が評価済みに変わった結果。
- バスを足すと診断範囲が208メッシュ（約63万人）広がった（練馬・杉並・世田谷・中野など、これまで空白だった地区）。そこには JR・私鉄駅の周りも含まれるので、全診断範囲で数えた未評価は 98,688 → 147,420 と増える。改修前と同じ地区で比べると、バスでさらに 96,509 → 81,667 に減っている。
- 残った未評価（81,667人）の最寄りの未収録駅: JR東日本・埼玉高速鉄道・西武・京王・東急・北総・京成・東京モノレール・舞浜リゾートライン・ゆりかもめ（鉄道3追加後の内訳）。

- サイズは 3MB 上限（test_data）に余裕があるので、追加の絞り込みはしていない。17〜23分は地域ごとの並列ビルド（`--region` と `--reindex`）で吸収できる範囲と判断した。重いと判断される場合は、`--whatif-top` を下げるか、東京の bbox を狭める。
- キャッシュ（cache/feed）: 新規16ファイル（大田区を含む）、合計約 27 MB。gitignore 対象。

## 実装
- `lifemap/odpt_adapter.py`: 認証API（`api.odpt.org`）、`needs_token()`、`access_token()`（環境変数 ODPT_ACCESS_TOKEN）、`file_url(path, token, query)`、`redact()`。
- `lifemap/fetch.py`:
  - `fetch_feed()`: トークン必須フィードは、キャッシュがあればそれを使う。キャッシュも無くトークンも無ければ警告して飛ばす（ビルドは続く）。取得に失敗した場合も警告して飛ばす。
  - `http_get()`: 例外文の URL を伏せ、元の例外は連鎖させない。
  - キャッシュ名は `odpt__<id>.zip`。
- `lifemap/build.py`:
  - 取得できたフィードだけでビルドする（`loaded_feed_defs`）。
  - フィード単位の `rail_covered` は、そのフィードを読み込めたときだけ未収録鉄道から外す（`covered_rail`）。トークンなしで地下鉄を飛ばした場合は、その駅が「未評価」に戻る。
  - 更新日の抽出を改善（`edo_20260715_001` 形式と `query.date`）。
- `regions.json`: 東京に13フィードを追加。名称を「東京都区部」にし、理由文を更新。
- 画面:
  - 静的版 `web/app.js`・`web/lib.js`: 出典欄の「キー不要」表記を条件分岐にし、ガイドラインの通知文 `ODPT_NOTICE` を追加。
  - ダッシュボード版 `panels.tsx`・`lib.ts`・`index.tsx`: 静的版と同じ変更。
- ダッシュボードのデータ: `npm run copy-data` は biz-realestate も上書きするため使わず、同じ odpt の11ファイルだけを `public/data/odpt/` へ `cp` した（copy-data と同じ結果になる）。ダッシュボード共通ファイル（registry.ts・contests-info.ts・shared・scripts/copy-data.mjs）は**変更していない**（作業ツリー上の変更は別部隊のもの）。
