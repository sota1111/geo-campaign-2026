# 衛星データ活用アワード 提案A 路面下空洞の実データ調査（情報部）

取得日: 2026-11-21（全出典とも同日に取得）。対象: contests/satellite-2026/app/proposal-a/ の「地中レーダ結果（架空）」を実データに置き換えられるか。
制約遵守: 読むだけ。外部へ POST なし。個人住所に結びつく使い方は提案しない。
調査上の限界（先に明記）: 情報部のこの回は Bash が使えず、XLSX（国交省の2ファイル）の中身は開けていない。列構成・座標の有無は「未確認」とした。PDF の表は画像として目視したため、小さい行名の読み取りは「要確認」を付けた。

## 結論（先に）
1. **点の座標つきの「空洞」「陥没」を、商用可・再配布可で公開している自治体・機関は、今回の調査では見つからなかった。** 空洞調査の結果は PDF の集計、陥没は国交省の路線名・地名単位の表が最も細かい。
2. 位置が最も細かい可能性があるのは、国交省「道路陥没発生箇所の詳細」（XLSX。路線名・地名・要因施設・大きさ）。ただし**座標の有無と地名の細かさは未確認**。
3. 下水道台帳（竣工年あり）・干渉SAR・「当たり」の3点が揃う場所は、**豊中市以外では見つからなかった**。豊中市の「当たり」も、国の全国特別重点調査（大口径管のみ）では 0 件と読み取れる。
4. したがって「架空の地中レーダ結果を実データに置き換える」は、位置単位ではできない見込み。代替は第5節。

### 3. 3条件が揃う自治体
- **豊中市（既存）**: 台帳（竣工日あり、CC BY 4.0）と干渉SAR は揃う。ただし**この地区の SAR は階級差が小さく（階級幅以内）、沈下の兆候はない**（README）。「当たり」は、国の特別重点調査で 0 件と読み取れる。位置つきの当たりは無い。
- **豊中市以外**: 3条件が揃う組合せは**未発見**。台帳側の制約が最大（竣工年つきで管渠の位置をオープンデータにしている市が見つからない）。SAR 側は埋立地などで沈下が大きい地域があり得るが（浦安市の埋立地で沈下継続を示す研究: <https://mdpi.com/2072-4292/10/8/1304>）、地理院の成果での階級差は未確認。台帳が無いので組合せにならない。
- 他市に広げる場合の条件: ①管渠の座標と竣工年のあるオープンデータ、②地理院の階級に 2 階級以上の差、③位置または細かい地名つきの陥没記録。①が最大の壁。

### 4. 代替案（位置データが無い場合）
| 案 | 内容 | 根拠 | 限界 |
|---|---|---|---|
| 案1 架空部分を外し、第2段階を「利用者が自分の調査結果を入れる枠」にする | 画面から架空の空洞結果と AUC を消す。第1段階（絞り込み・選定）は実データで残す | 実データだけで作れる範囲に限る。偽の精度を示さない | 「戻す」の体験が弱くなる。審査での見せ方は偵察隊の比較が要る |
| 案2 市区町村・管理者区分の件数で検証 | 国交省の陥没件数（令和6年度）を、国総研の布設年度別管路延長（管理者区分別）と並べ、古い管が多い区分ほど下水道起因の割合が高いかを見る。**位置単位の検証ではない** | PDF で下水道起因の件数は 管理者区分別に確認済み（例: 特別区 52%、政令市 25%） | 集計単位が粗い（生態学的誤謬）。件数は発見・報告の差を含む。因果は言えない。区分が 3〜4 個では統計的な検定はできない（推測） |
| 案3 02.xlsx の地名で町丁目単位に集計 | 地名が町丁目まで細かければ、豊中市の陥没を町丁目で集計し、台帳の竣工年の中央値と比べる | 要確認1 が解決すれば可能 | 豊中市の件数が少ない可能性が高い（推測）。件数が数件では検証にならない。**地名が細かいと個別の道路・住所に近づく**ので、町丁目より細かくは出さない |
| 案4 報道された陥没地点は使わない | 報道の地点を人手で集めない | 選択バイアス（大きな事故だけ報じられる）、再現できない、記事の転載権利、地点が個人の住所に近いことがある | 実データの当たりを得る手段を一つ手放す |

## registry更新提案（差分。registry.json は変更しない）
1. satellite-2026 の proposal-A の実データ範囲を「衛星・道路・下水道台帳は実データ、空洞結果は架空（位置単位の実データは公開なし）」と明記する案。
2. 地理院 SAR の利用条件の欄に「e-gov は政府標準利用規約、測量法上の承認は要確認」を追記する案。
3. 統合ダッシュボードの sat-a が旧版の架空データ（data/sample.json）を読んでいる点を、課題として登録する案。置換先は data/toyonaka.json（工兵の作業）。
4. brief.md には空洞・陥没・実データの記述が見当たらない（grep で該当なし）。差分は無いが、追記を提案する。

## 推奨（短く）
- **豊中市のまま、地中レーダ結果は「架空」と明示して残すか、案1で外す。** 位置単位の実データで置き換えるのは、現時点では根拠がない。
- 先に **02.xlsx を開いて確認**（要確認1）。座標か細かい地名があり、豊中市の件数が十分なら案3、そうでなければ案2を補助の検証として添える。
- 他の自治体へ移す理由は、現時点では無い（台帳の竣工年つきデータが見つからない）。
- ダッシュボードの sat-a は、豊中市版（data/toyonaka.json）に付け替える。
